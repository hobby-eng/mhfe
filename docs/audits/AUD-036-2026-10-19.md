### Findings

#### AUD-036-BLD001 — Low — Windows external observer does not constrain the DACL threat context

- **Category:** BLD.
- **Status:** Fixed.
- **Verification:** Candidate native CI pending.
- **Release blocking:** Yes, because required native acceptance is incomplete.
- **Affected files:** `src/bin/mhfe/protect/windows/tests.rs`, `src/bin/mhfe/protect/windows/tests/observer.rs`.
- **Reproduction:** Run the Windows native process-protection test at c059b1a on the hosted runner.
- **Expected behavior:** Both external observers exercise ordinary same-user access without privileged DACL bypass.
- **Observed behavior:** Strict DACL equality, memory_access and startup passed, but the fresh negative VM_READ open succeeded; 199 CLI cases passed and one failed.
- **Impact:** The test can fail outside the documented DACL threat model. This does not demonstrate ordinary-user access after hardening; baseline effective privileges were not measured.
- **Recommended fix:** Prepare the same ordinary observer for both controls: reject impersonation/SYSTEM, disable only SeDebugPrivilege and independently read back its disabled/absent state.
- **Implemented fix:** A test-only shared observer helper performs those checks with owned handles and bounded aligned token metadata; every original grant/denial assertion remains.
- **Required verification:** Native Windows compilation and paired ordinary VM_READ/WRITE_DAC grants/denials, plus startup and optimized CLI/pseudo-console acceptance.
- **Evidence:** Local `commands/native-policy-pushed-ci-windows-red.log`, SHA-256 `edfc6a1fb2268bd23019cb453204f37a573eec3563383c45da2c96c4ff53c38f`.

#### AUD-036-BLD002 — Low — Damaged macOS known-answer fixtures lose hardened-runtime signing

- **Category:** BLD.
- **Status:** Fixed.
- **Verification:** Candidate native CI pending.
- **Release blocking:** Yes, because required native acceptance is incomplete.
- **Affected files:** `scripts/terminal_suite/self_test.py`.
- **Reproduction:** Run the native PTY suite against the optimized runtime-signed c059b1a CLI.
- **Expected behavior:** Flipping one known-answer bit changes the tested answer while retaining the original runtime-policy conditions.
- **Observed behavior:** damaged_copy re-signed with bare codesign --force --sign -, omitting runtime. Wrong-answer startup/menu refusals passed, then exact full-report comparison failed because the damaged copy reported hardened runtime unverified.
- **Impact:** The fixture changes a second independent condition and blocks native terminal acceptance. The original CLI passed its runtime verification and ordinary self-tests.
- **Recommended fix:** Reuse the shared hardened-runtime signing and verification script after writing/chmod; propagate failure before executing the modified fixture.
- **Implemented fix:** The Darwin-only path calls absolute ROOT/scripts/harden-macos.sh with check=True and timeout30; original expected reports and known-answer assertions are byte-identical.
- **Required verification:** Red/green public helper dispatch and signer-refusal controls, followed by real macOS signing, damaged-known-answer and terminal suite execution.
- **Evidence:** Local `commands/native-policy-pushed-ci-macos-red.log`, SHA-256 `7967418723ccee73ebc0bfd080eea97ba7422f5e0dccf0e3466baa278dfa7732`.

The Windows baseline privileges were not recorded. Its observer now verifies the final ordinary context, while successful child output may be captured/discarded; passing does not establish debug_before=true. SYSTEM or impersonation fixtures fail explicitly, and every original positive and negative access assertion remains. Production tokens and host settings are unchanged.

The macOS fixture already re-signed its modified binary, but omitted the runtime option. It now uses the existing signing/strict-verification/runtime-flag script. Both damaged-vector variants share that helper. The deliberately unsigned packaging negative control is unchanged, as are every expected self-test row and wrong-known-answer refusal.
