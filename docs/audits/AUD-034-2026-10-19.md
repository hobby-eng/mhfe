### Platform interpretation

Linux's [proc documentation](https://docs.kernel.org/filesystems/proc.html) describes partial-read races and also promises nonoverlapping progress. The retained duplicate-prefix stream is reported as the observed runtime symptom, not a universal kernel guarantee. The parser still demands exact dd and continuous, nonoverlapping coverage of every owned page; no unrelated prefix flag can establish that coverage.

The macOS positive control failed EPERM. The [Apple ptrace contract](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/ptrace.2.html) and [XNU implementation](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/mach_process.c) distinguish authorization from PT_DENY_ATTACH enforcement. The explicit CI opt-in elevates only the fixed public monitor and its named probe subprocesses using noninteractive sudo, which [hosted runners provide](https://docs.github.com/en/actions/reference/runners/github-hosted-runners#administrative-privileges). Cargo, the rest of the suite and production commands are not elevated. The monitor must observe attach/stop/detach success, then the actual protected child's SIGSEGV after its ready-for-attach marker. A denied control still fails; sudo's signal relay is not the oracle.

## Findings and remediation

### AUD-034-BLD001 — Low — Pending-buffer reader test literals omit the Windows console field

- **Category:** BLD
- **Status:** fixed
- **Reproduction:** At 8040797, run cargo test --locked on Windows MSVC.
- **Expected:** Both wiping fixtures compile on every supported native platform.
- **Observed:** Windows CI reports E0063 twice at standard_input.rs:229 and :243.
- **Impact:** Native tests cannot compile; no production-input failure is demonstrated.
- **Recommended fix:** Create fixtures through StandardInput::new and set the same bytes/ranges.
- **Implemented fix:** Both fixtures use the real constructor; production code and assertions are unchanged.
- **Required verification:** Preserve byte-wiping/scalar assertions and obtain native Windows compilation.
- **Release blocking:** true; the corresponding required native gate failed.

### AUD-034-FUN001 — Low — Unrelated smaps prefix ordering can refuse concurrent native C calls

- **Category:** FUN
- **Status:** verified
- **Reproduction:** Run the concurrent_c_calls_keep_verified_work_area_protection regression on the former parser.
- **Expected:** Every owned page requires exact dump-exclusion coverage; unrelated prefix records do not refuse that coverage.
- **Observed:** Actual C concurrency returned MemoryProtection; diagnostic booleans locate the overlapping record wholly before the owned range, before any owned coverage. The minimized deterministic fixture also fails before the fix.
- **Impact:** A valid concurrent operation may fail closed. No wrong cryptographic output or exposed work area was demonstrated.
- **Recommended fix:** Track strict progress over owned pages without imposing global prefix ordering.
- **Implemented fix:** covered_owned_pages gates the monotonic-coverage rule; all owned-page checks and finite read bounds remain.
- **Required verification:** Deterministic red/green, unchanged missing-dd/gap/owned-overlap/I/O/budget refusals, concurrent actual C calls and independent known answers.
- **Release blocking:** true; the corresponding required native gate failed.

### AUD-026-BLD003 — Low — Follow-up: hosted macOS lacks authorization for the unprotected PT_ATTACH control

- **Category:** BLD
- **Status:** fixed
- **Reproduction:** At 8040797, run the macOS portable job without an authorized public probe monitor.
- **Expected:** A successful attach/stop/detach control precedes the protected child signal assertion.
- **Observed:** The control returns EPERM and the paired test correctly fails UNAVAILABLE; this does not verify target hardening.
- **Impact:** The required macOS native acceptance gate cannot establish its positive precondition.
- **Recommended fix:** Explicitly authorize only the fixed public-data monitor and its named probe children in hosted CI.
- **Implemented fix:** An explicit test-only opt-in invokes /usr/bin/sudo -n for the fixed monitor; actual child signals are checked inside it, before sudo result relay. No OS policy is changed.
- **Required verification:** Real native control success and protected SIGSEGV, exact one-test/completion markers, unchanged production privilege behavior.
- **Release blocking:** true; the corresponding required native gate failed.
