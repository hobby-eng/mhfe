# AUD-049 — Full audit of mhfe after the move onto mhfe-core 0.3.0 and secret-protection-core 0.2.0

## Release decision

**INCOMPLETE**, ordinary audit. Two release-blocking findings were found and fixed: the reproducible
build's tests failed in their container (AUD-049-BLD001, verified in a new PID and user namespace)
and the release's fuzz job could not compile (AUD-049-BLD002, fixed, verified only by the next tag).
Required results are missing: Miri stops at the first call into secret-protection-core, the Intel
macOS program ran in no CI row at the reviewed commit (added at the remediation commit), and the
browser package runs in real browsers only by hand and for a release.

### Findings

#### AUD-049-SEC001 — Low — The browser opener stays in the server's session and can open its terminal

- **Category:** SEC.
- **Severity:** low.
- **Status:** verified.
- **Release blocking:** false; Not release-blocking: fixed with the change that touches its code.
- **Affected files and builds:** `src/bin/mhfe/serve.rs:305-323`.
- **Reproduction:** Start `mhfe serve`: the opener and the browser it starts run in a process group
  of their own but in the server's session, so /dev/tty still opens for them.
- **Expected behavior:** CORE-55: the narrowest form; the comment says they get no terminal.
- **Observed behavior:** process_group(0) keeps the session and with it the controlling terminal.
- **Impact:** Where the kernel allows TIOCSTI, the browser or its opener could type into the shell
  after serve ends.
- **Evidence:** Source reading at the reviewed commit.
- **Recommended fix:** Start the opener with setsid in pre_exec, a session of its own without a
  controlling terminal.
- **Required verification:** A Linux test starts a shell through the same helper and checks that it
  leads its own session.

#### AUD-049-SEC002 — Low — Names shown escaped miss some invisible formatting characters

- **Category:** SEC.
- **Severity:** low.
- **Status:** verified.
- **Release blocking:** false; Not release-blocking: fixed with the change that touches its code.
- **Affected files and builds:** `src/bin/mhfe/hidden_input.rs:973-980`,
  `src/bin/mhfe/style.rs:654`.
- **Reproduction:** `escaped("/tmp/tool\u{E0041}.html")` returns the tag character as it is; U+00AD,
  U+180E and U+FFF9 to U+FFFB pass too.
- **Expected behavior:** Its documentation: invisible formatting characters are shown escaped.
- **Observed behavior:** Only the bidirectional controls, zero-width characters and the byte order
  mark are covered.
- **Impact:** A file name can hide characters a person does not see.
- **Evidence:** Source reading at the reviewed commit.
- **Recommended fix:** Add the soft hyphen, the Mongolian vowel separator, the interlinear
  annotation marks and the tag characters.
- **Required verification:** The unit test lists U+00AD, U+FFF9 and U+E0041 among the characters not
  shown.

#### AUD-049-FUN001 — Low — The swap question comes before the stop for open memory

- **Category:** FUN.
- **Severity:** low.
- **Status:** verified.
- **Release blocking:** false; Not release-blocking: fixed with the change that touches its code.
- **Affected files and builds:** `src/bin/mhfe/main.rs:296-303`, `src/bin/mhfe/protect.rs:434-455`.
- **Reproduction:** In a container with the host's swap on a disk and no user systemd, a secret
  command asks whether to go on with unencrypted swap, then stops because other programs could read
  its memory.
- **Expected behavior:** A command that will stop asks nothing first.
- **Observed behavior:** keep_off_swap asked before isolation and the checks at start.
- **Impact:** A pointless question, answered for nothing.
- **Evidence:** Source reading at the reviewed commit.
- **Recommended fix:** Keep the restart before isolation, and ask after the checks at start
  (ask_about_swap).
- **Required verification:** The tool's tests and the terminal suite pass with the question after
  the checks.

#### AUD-049-FUN002 — Low — The swap restart starts the program by its path again

- **Category:** FUN.
- **Severity:** low.
- **Status:** accepted.
- **Release blocking:** false; Not release-blocking: fixed with the change that touches its code.
- **Affected files and builds:** `src/bin/mhfe/protect.rs:478`, `src/bin/mhfe/menu.rs:316-323`.
- **Reproduction:** On a system that restarts in a scope without swap, replace the file at the
  program's path between the start and the restart.
- **Expected behavior:** The program that runs is the one the person started, as the menu ensures on
  Linux.
- **Observed behavior:** systemd-run is given the program's path, so the file now at that path runs.
- **Impact:** Anyone who can replace the mhfe file can run code in the next command, as SECURITY.md
  says already.
- **Evidence:** SECURITY.md, section Limits, at the reviewed commit: "the swap restart, and the menu
  on other systems, start the program by its path again".
- **Recommended fix:** Keep the documented limit; systemd-run starts the program in a new process of
  the user manager, which cannot take the program's own file.
- **Required verification:** None: accepted as documented.

### Informational observations and recommendations

- WSL2 distributions may run in a PID namespace of their own; if so, every secret command stops
  there with the Linux message. Not verified.
- The menu's stop handler could, if its thread stalled for more than 50 ms between marking and
  killing, reach a process that reused an ended command's number. Not reproduced.
- On macOS the channel census may count a shared mapping as left open, which would give a standing
  warning; no macOS test asserts it.
- The library's tests do not run on wasm32 in CI; the browser package's own checks run in real
  browsers by hand and for a release.
- The fuzz targets start from an empty corpus without a BIP39 dictionary, so the repair and search
  paths are reached rarely; a seed corpus would help.
- fuzz/Cargo.lock is not covered by Dependabot; a gate that compares its shared versions with
  Cargo.lock would catch drift.
- SECURITY.md asks for reports through public issues while private vulnerability reporting is
  enabled on the repository; the channel should be one or the other.

### Assessment and limitations

The evidence shows the move onto mhfe-core 0.3.0 and secret-protection-core 0.2.0 working on every
native runner GitHub offers, with stricter isolation that stops a command when other programs could
read its memory, and with the hidden input, the menu and every command's prompts checked in real
pseudo-terminals. It does not show Miri's view of the unsafe code, the Intel macOS program at the
reviewed commit, the browser package in a browser, the release workflow's new jobs, which run only
at a tag, or the hardened runtime's refusal on a Mac with System Integrity Protection on. The
construction itself has not been reviewed by independent cryptographers.
