### Findings

#### AUD-026-BLD003 — Low — macOS synthetic ptrace signal can be consumed by the Rust tracer

- **Category:** BLD.
- **Status:** Fixed.
- **Verification:** Native acceptance pending.
- **Release blocking:** Yes, until the required native checks pass.
- **Reproduction:** Run the ordinary macOS attachment test at 8ebba34 on the authorized native CI host.
- **Expected behavior:** An attachable control followed by the protected tracer terminating with real SIGSEGV.
- **Observed behavior:** The control succeeded; protected PT_ATTACH returned EBUSY and the tracer panicked exit101. The monitor saw no terminating signal.
- **Impact:** The required native protection test fails; no successful protected attach or private-data exposure is demonstrated.
- **Recommended fix:** Restore/read back SIG_DFL only in both disposable public tracers, after disabling core files.
- **Implemented fix:** default_segv_delivery sets and reads back SIG_DFL; all original attach and signal assertions remain.
- **Required verification:** Native macOS paired PT_ATTACH control and real protected SIGSEGV; no errno-only or synthetic replacement fallback.
- **Evidence:** Local `macos-native-followup.log`, SHA-256 `8d20791ca2c8a7c363f099166bb72e25bfc224f2194f56563b61e9e5fe32d2c7`.

#### AUD-035-FUN001 — Medium — Windows native startup refuses the stored process DACL

- **Category:** FUN.
- **Status:** Fixed.
- **Verification:** Native acceptance pending.
- **Release blocking:** Yes, until the required native checks pass.
- **Reproduction:** Run Windows protection and startup tests at signed 8ebba34.
- **Expected behavior:** Stored process policy matches the requested restricted owner and SYSTEM policy; startup accepts the read-back.
- **Observed behavior:** All 429 library tests passed; 198 CLI cases passed and two failed because memory_access was Differs after harden.
- **Impact:** Native startup fails closed, preventing secret operations on the affected host; no unauthorized access is demonstrated.
- **Recommended fix:** Request process-specific SYSTEM rights instead of generic GA; preserve strict read-back and external before/after probes.
- **Implemented fix:** SYSTEM uses 0x001fffff, matching the pinned SDK PROCESS_ALL_ACCESS. Owner rights, strict read-back and production harden entry point remain.
- **Required verification:** Native Windows startup, exact DACL equality and fresh external VM_READ/WRITE_DAC refusal following successful unprotected controls.
- **Evidence:** Local `windows-native-followup.log`, SHA-256 `49e6317019d65126980cf62d8f1536ffe8db754fc67f0776f00ecdff12500b71`.

The Rust explanation is supported by the pinned 1.99.0 source and a local isolated signal control; the baseline macOS handler was not inspected. For Windows, GA expansion is a candidate explanation, not an observed baseline ACE dump. Exact native reruns must settle acceptance. The strict full-ACL comparison remains unchanged and no representation mismatch is ignored.
