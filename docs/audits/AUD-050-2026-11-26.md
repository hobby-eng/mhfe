### Dependency and protection integration

The root and fuzz lockfiles resolve one instance of each security crate. The pinned `mhfe-core 0.3.0` archive matches both locks, the [upstream release asset](https://github.com/hobby-eng/mhfe_core/releases/tag/v0.3.0) and the registered source commit `24a0b70df487de488dc1f4b2b5573896ef1dcff4`. All 20 packaged source files under `src/` match the tag byte for byte. The archive includes a separate Cargo distribution manifest.

| `secret-protection-core 0.2.0` | `27c89c8b0707b953e159a053fbc22e240ca221010229b5759803c6d314548ef7` |

- No native cipher, native Argon2 or Reed–Solomon implementation was found in the caller. The direct SPC use selects isolation options and the descriptor census. The application owns descriptor closure, tty modes, signal routing, swap, memory admission and raw stdin.
- Secret-reading commands enter the same startup gate. The menu delegates to subprocesses. Serve, help, version and the public-data benchmark do not collect wallet secrets. Windows documents the limits of its isolation.
- The browser retains the vendored reference C engine only for its WASM package. The same Rust core supplies suite and container processing.

The API audit traced `Seed::derive` errors, borrowed check-word indices, and the common rekey confirmation gate through CLI and WASM. Full-cost vectors were excluded. The current Unicode 18 behavior and earlier-version compatibility note remain part of the pinned core and specification contract.

### Findings

#### AUD-050-SEC001 — Medium — Cancellation can move private recovery output onto the main terminal screen

- **Status.** Open. Release blocking.
- **Affected files and builds.** Interactive native decrypt with several passwords and its private scroll screen on Unix and Windows.
- **Method.** Static trace of concurrent rendering and cancellation. No runtime reproduction was run.
- **Expected behavior.** A cancellation leaves the alternate screen after all secret writes finish and prevents new secret writes during the transition.
- **Observed behavior.** The cancellation handler takes the drawing lock before restoring the terminal and changing screens. The initial password heading and scroll renderer write secrets without this lock. The cancellation message and process exit follow the screen change.
- **Impact.** A concurrent cancellation can move a password or recovered words to the normal terminal and its scrollback. The source establishes the race. No runtime disclosure was demonstrated.
- **Evidence.** src/bin/mhfe/decrypt.rs:373–382, 429–455; src/bin/mhfe/scroll.rs:108–151; src/bin/mhfe/hidden_input.rs:153–193; src/bin/mhfe/terminal.rs:391–424, 549–563, 828–836. The ordinary phrase writer takes the guard. Related AUD-045-SEC001 covered earlier paths.
- **Recommended fix.** Serialize private output and alternate-screen transitions under one ownership rule. Avoid recursive lock acquisition in nested helpers.
- **Required verification.** Check the private rendering protocol during cancellation with public fixtures in the native terminal suites. Verify the cleanup and retained-output policy.

#### AUD-050-BLD001 — Medium — Release attestation does not bind the complete asset set to the canonical build

- **Status.** Open. Release blocking.
- **Affected files and builds.** Tagged release workflow, canonical artifact downloads, attestation and draft publication.
- **Method.** Static comparison of the files named by the canonical digest with the inputs admitted by later jobs.
- **Expected behavior.** Every attested and drafted file has an expected role and is bound to the canonical build or to the verified manifest assembled from it. Acceptance jobs test those bytes.
- **Observed behavior.** Only canonical.sha256 is bound to the canonical job output. Verification trusts all downloaded .sha256 files and compares archive names only. The next jobs attest and draft a wildcard over the directory. Browser and macOS test jobs unpack the canonical download before checking the building job's digest.
- **Impact.** With control of the cross-job artifact contents, additional files can reach the attested draft without canonical-build provenance. Existing archives still have to satisfy the anchored manifest. The draft and independent maintainer verification remain separate controls.
- **Evidence.** .github/workflows/release.yml:60–73, 94–113, 129–141, 188–227, 233–255. AUD-049-BLD005 remediation anchors one manifest but leaves a broader trust set.
- **Recommended fix.** Use only the anchored manifest as authority, enforce the exact expected files, and bind the bytes used by acceptance jobs, attestation and the draft to that result.
- **Required verification.** Verify the allowlist and digest policy, then compare accepted, attested and drafted artifact names and digests on a release candidate.

#### AUD-050-API001 — Low — The address search description can panic on mixed root shapes

- **Status.** Open. Bounded to the affected surface.
- **Affected files and builds.** Native Rust AddressSearch::new. The CLI and browser describe one address text at a time.
- **Method.** Static trace of the public address slice and the different search-root lengths.
- **Expected behavior.** The public description accepts supported collections and describes them correctly, or its input boundary refuses an unsupported combination.
- **Observed behavior.** The formatter uses the first root length to index all roots. Dash Platform contributes three steps. Conventional roots contribute two. The formatter can index past the shorter root or omit a step in the reverse order.
- **Impact.** A library caller passing heterogeneous addresses can lose the process under the release abort profile or see an incomplete description. The CLI and browser parse one address per call.
- **Evidence.** src/wallet.rs:405–424, 913–955, 1012–1031, 1126–1146. The plural search deliberately distinguishes different programs in its input slice.
- **Recommended fix.** Describe groups with different root lengths separately, or validate an explicit same-address input contract. Align the count with the actual search.
- **Required verification.** Cover mixed root lengths in both orders and compare the described work with the actual search.

#### AUD-050-API002 — Low — Explicit-path address verification skips the cancellation callback

- **Status.** Open. Bounded to the affected surface.
- **Affected files and builds.** Native Rust find_address_until and find_addresses_until with an explicit path.
- **Method.** Static comparison of explicit and standard paths with the public cancellation contract.
- **Expected behavior.** The caller's stop request takes effect before deriving an address.
- **Observed behavior.** The explicit branch derives and compares without calling stopped. The standard path asks before each candidate derivation.
- **Impact.** A cancelled call can still derive and return a result or an error. The effect is bounded to the explicit path.
- **Evidence.** src/wallet.rs:1083–1125, 1151–1176.
- **Recommended fix.** Honor the stop callback at the shared entry and before explicit-path comparison at the documented granularity.
- **Required verification.** Cover an already stopped explicit-path call and preserve existing standard-search and successful explicit-path results.

#### AUD-050-API003 — Low — Browser passphrase copying precedes admission bounds

- **Status.** Open. Bounded to the affected surface.
- **Affected files and builds.** Browser wallet and core requests that accept a BIP39 passphrase and their WebAssembly bindings.
- **Method.** Static trace of passphrase entry, byte copy, worker transfer and the downstream Rust check.
- **Expected behavior.** Representable inputs are admitted within a documented host bound before transfer and normalization. Excess lengths receive a controlled failure.
- **Observed behavior.** JavaScript validates type and text representation, then copies or encodes without a length bound. The binding receives allocated bytes before the core applies its normalized limit.
- **Impact.** Large caller-supplied input can trigger disproportionate allocation or tab or worker failure before the typed length error. The impact is local browser availability.
- **Evidence.** web/runtime.js:469–510; web/wallet.js:57–81, 108–117; src/wasm_api/wallet.rs:50–71. The CLI applies an independent input bound.
- **Recommended fix.** Enforce a documented transport bound before owning copies. Preserve the core's Unicode normalization and normalized-byte limit.
- **Required verification.** Check string and byte admission limits, including boundary Unicode and unchanged outputs for accepted input.

#### AUD-050-DOC001 — Low — The target and developer guides lag the active repository configuration

- **Affected files and builds.** Developer documentation and audit target inventory.
- **Method.** Compare the guide entries with active manifests and the release workflow.
- **Expected behavior.** The target inventory lists configured harnesses and the developer guide identifies the current dependency source.
- **Observed behavior.** TARGETS.md still lists three fuzz harnesses. The fourth, http, is selected by release.yml. DEVELOPMENT.md still describes mhfe-core as pinned to a Git revision.
- **Impact.** A manual review can miss the HTTP harness or take the wrong source as its dependency reference.
- **Evidence.** docs/audits/TARGETS.md:29–33; docs/DEVELOPMENT.md:88–92; fuzz/Cargo.toml; Cargo.toml:35–40; .github/workflows/release.yml:156–177.
- **Recommended fix.** List all active targets and state the registry pin and lockfile checksum policy.
- **Required verification.** Compare the guides with cargo metadata, both lockfiles and release.yml.

#### AUD-050-ARC001 — Low — The HTTP fuzz oracle omits parts of its stated admission invariant

- **Status.** Open. Bounded to the affected surface.
- **Affected files and builds.** fuzz/fuzz_targets/http.rs, an active release fuzz target.
- **Method.** Compare the harness header with the checks on accepted responses and the separate server unit tests.
- **Expected behavior.** The fuzz oracle independently checks which request heads can return the page, including exactly one expected Host, with an empty body on HEAD.
- **Observed behavior.** The successful-response branch checks the method and request path prefix. It does not assert the Host contract or distinguish GET and HEAD bodies. It takes its expected header list from the production parser module.
- **Impact.** A generated case can traverse relevant code without detecting these classes of regression. Existing serve unit tests separately check Host and HEAD behavior.
- **Evidence.** fuzz/fuzz_targets/http.rs:1–6, 31–53; src/bin/mhfe/serve.rs:419–452. Related AUD-049-ARC001 added the harness.
- **Recommended fix.** Assert the core admission and response-boundary properties through independent expectations while keeping the fixed parser tests.
- **Required verification.** Check that the harness rejects incorrect acceptance and response outcomes while preserving valid request cases.

#### AUD-050-ARC002 — Low — The Linux namespace test can pass before checking descriptor and thread invariants

- **Status.** Open. Bounded to the affected surface.
- **Affected files and builds.** Linux x86-64 and ARM64 isolation fixture in native and container test environments.
- **Method.** Static comparison of the child result ordering with the parent success cases.
- **Expected behavior.** An expected refusal for open process memory proves that the command stopped. Independent claims about descriptor closure and single-thread entry need their own assertions.
- **Observed behavior.** The parent accepts MEMORY_OPEN. The child chooses that result before checking INHERITED_OPEN or LATE, so those checks are not enforced on a run that reaches MEMORY_OPEN.
- **Impact.** A passing namespace run with open memory verifies a refusal path, while descriptor closure or whole-process ordering can regress without failing that run.
- **Evidence.** src/bin/mhfe/protect.rs:969–990, 1025–1041. Related retained namespace work AUD-049-BLD001.
- **Recommended fix.** Report the gate result separately from descriptor and ordering predicates, and test the remaining predicates on an environment that can observe them.
- **Required verification.** Compare the independent predicates in the native and namespace fixtures, with explicit outcomes for checks that cannot be made.

- The repository byte inventory is complete. Independent line-by-line coverage and exhaustive CORE conformance remain unverified. Git signature headers and UTC timestamps were inspected. Local cryptographic verification of the MHFE commit signatures was not performed.
