## Review evidence

### Scope and methodology

The review follows the shared audit procedure. It inventories 679 regular tracked root files and the specification gitlink (188 tracked entries). Native and browser reviewers traced 150 distinct files; the coordinator covered the other 99 active/vendor files. The 430 historical audit files were classified as frozen records. Source traces cover encryption, recovery, check, rekey, new phrases, hidden wallets, repair, repair words, passwords/dice, serving, self-tests, benchmark and wallet/reference helpers. Inventoried tests and generated data were not mistaken for independently rederived results.

Full-cost vectors were left out by decision. The normal bounded fixture tests ran; the separate `published-rounds --check` generator comparison, ignored full-size tests, `self-test --vectors`, full package run and whole `parity` task were not separately invoked. `parity` includes a real full-cost native vector. The latest retained vector CI success belongs to core `d2039488`, not the adopted `523f9e4`.

The core is used correctly at the new `ControlFlow` seam: only Continue returns a value, and a cancelled creation check publishes no verified result or repair card. This audit reviews the integration; it does not repeat a complete upstream core or RustCrypto audit.

### Tools, skills and environment

Rust 1.99.1, Cargo 1.99.1, wasm-bindgen 0.2.129, Emscripten 6.0.12, dprint 0.63.0, Python 3.14.4 and Docker 29.9.2 were already installed. RustSec checked 114 packages against 1,402 advisories with no vulnerabilities or warnings. The browser versions are Chrome 155.0.8059.79 and Firefox 158.0.

Used `wallet-full-audit`, `wallet-release-verification`, `wallet-security-review`, `audit-context-building`, and scoped Rust/zeroization review checklists. No new skill/toolchain/scanner was installed. A new Rust audit-only write-scheduling probe supplies the terminal reproduction; its code was independently reviewed. No automated native plugin scan, assembly erasure analysis, fuzz or mutation campaign was executed.

Heavy commands ran one at a time through the shared lock and memguard. Build/browser scopes were capped at 3 GiB with swap forbidden inside those scopes; machine swap, CPU and temperature settings were unchanged. Two small read-only reviewers shared results. Native observed peak was 306,855,936 bytes; browser observed peak at capture was 2,065,276,928 bytes.

### Findings

#### AUD-045-SEC001 — Medium — Secret renderers other than typed lines and print_phrase can write after Ctrl+C has returned to the main screen

- **Category / status:** SEC / fixed (remediation of 2026-11-03, see Remediation and follow-up).
- **Release blocking:** true; The documented private-screen guarantee fails for a supported password command after an ordinary cancellation.
- **Affected files and builds:** [{"file": "src/bin/mhfe/diceware.rs", "start": 232, "end": 238}, {"file": "src/bin/mhfe/made_password.rs", "start": 208, "end": 217}, {"file": "src/bin/mhfe/choice.rs", "start": 395, "end": 427}, {"file": "src/bin/mhfe/hidden_input.rs", "start": 184, "end": 191}, {"file": "src/bin/mhfe/terminal.rs", "start": 360, "end": 380}]
- **Reproduction:** Build the retained AUD-045 Rust harness, then run aud045-probe <reviewed target/release/mhfe> <libaud045_probe.so> inside a Linux MemorySwapMax=0 user scope. It types public dice 11111 for mhfe password --dice --words 1, signals the real child and schedules its original writes. See the harness README for commands.
- **Expected behavior:** After cancellation the main terminal screen/scrollback contains no password or secret phrase; renderers and the handler obey the shared DRAWING gate.
- **Observed behavior:** On the unchanged release executable: typed_public_dice=true; signalled_at_write=true; handler_wrote_leave=true; exit=exit status: 130; word_after_leave=true. The final run exits 1 because the privacy assertion fails.
- **Impact:** A generated password can reach the main terminal screen and scrollback when the person cancels during output. The natural timing window is narrow and was forced by the audit scheduler. No wrong cipher output or remote compromise was demonstrated.
- **Evidence:** ["Local AUD-045-evidence/render-race-final.log and its command record; SHA-256 c5743e2d51c55afdcfc87e02facb42beb5b9cf5d45e40864e2bf6d035e0158a4", "Independent native/harness-review-final.json; source trace independently challenged by browser reviewer."]
- **Independent challenge:** The interposer forwards original descriptors, bytes and counts. It neither inserts the password nor a leave-screen escape.
