### Architecture, readability and recommendations

The overall structure is appropriate: small protocol modules, validated password/work-factor types, an explicit Argon2 engine trait, a narrow unsafe FFI module, and separate CLI and worker adapters. There is no reason to force inheritance or additional classes onto this Rust/functional design. Double quotes and a 100-column Prettier target are consistent; Rust correctly retains rustfmt defaults.

- **Real-browser CI (normal):** Promote a self-contained reduced-cost Chromium/Firefox smoke suite into routine CI. Current CI exercises Emscripten under Node and a stand-in client worker; this audit adds actual Blob workers, CSP, transfer, cancellation and callback handling from the canonical archive. Avoid depending on a sibling checkout in the permanent CI version. Locations: `.github/workflows/ci.yml`, `docs/audits/AUD-006-harnesses/browser.mjs`.
- **Callback contract (normal):** Explicitly say page callbacks must be synchronous, or deliberately implement and test Promise rejection handling. An async callback that rejects currently produces an unhandled rejection while the operation continues and can resolve. Existing wording promises handling when a callback throws, so this is recorded as a scope clarification, not a failure of the tested synchronous contract. Locations: `web/client.js:252`, `web/client.d.ts:37`.
- **Memory admission (normal):** Consider container-aware Linux limits (cgroup v2/v1) and configurable headroom; /proc/meminfo is a host estimate and a concurrent workload can invalidate it. Keep allocation failure explicit and never silently lower the work factor. Release the Mach host send right if memory estimation will be called repeatedly in long-lived integrations. No OOM or real macOS port-exhaustion experiment was performed. Locations: `src/engine/ffi.rs:297`, `src/engine/native.rs:77`.
- **Types and invariants (deferred):** For a future API revision, consider a validated mnemonic-length enum and constructors/getters for address network/type and search limits. They would make invalid combinations harder to construct; current operational paths validate lengths before KDF and use small search defaults. Avoid a breaking refactor solely for OOP style. Locations: `src/mhfe.rs:27`, `src/wallet.rs:70`, `src/wallet.rs:215`.
- **Comment precision (deferred):** Describe the verifier as an internal consistency check, not password authentication; distinguish the 1024 normalized-byte password bound from longer valid pre-normalization input; update the argon2Engine cross-reference to web/argon2-engine.js. These are small clarity edits, not new algorithm findings. Locations: `src/packing.rs:4`, `src/bin/mhfe/terminal.rs:18`, `src/engine/browser.rs:18`.
- **Module size and layout (deferred):** Keep the present functional core and trait-based engine boundary. Large files contain substantial tests/help, so line counts alone do not justify splitting them. If these features grow, separate address parsing from BIP32 derivation and HTTP parsing from launcher selection at their existing function seams. Retain explicit cleanup and straightforward control flow. Locations: `src/wallet.rs`, `src/bin/mhfe/serve.rs`, `src/bin/mhfe/check.rs`.
