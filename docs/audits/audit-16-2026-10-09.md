#### AUD-016-API001 — Medium — Native decoy search cannot cancel an address comparison already in progress

- **Category:** API.
- **Severity:** medium.
- **Status:** open.
- **Release blocking:** false; The demonstrated failure requires a very large caller-selected native address scope. No secret compromise or ordinary default-scope failure was demonstrated.
- **Affected files and builds:** [src/search.rs:128](../../src/search.rs); [src/search.rs:284](../../src/search.rs); [src/search.rs:289](../../src/search.rs); [src/search.rs:309](../../src/search.rs); [src/wallet.rs:971](../../src/wallet.rs); native library decoy address search with two missing words and a large scan_gap.
- **Reproduction:** Run target/aud016-core-public-probe through cancel_watchdog.py. The public 32-byte zero entropy phrase has words 23 and 24 replaced by ?. ContainerSearch::new enumerates 16,384 candidates. search_decoy compares against the valid Bitcoin example address 1BoatSLRHtKNngkdXEeobR76b53LETtpyT with scan_gap=2^31 and no explicit path. The first progress callback returns MhfeError::Cancelled. The Linux watchdog uses one allowed CPU and kills the process if the call has not returned two seconds after that callback.
- **Expected behavior:** The documented progress callback error stops the search, including work currently evaluating its candidates, and returns Cancelled without scanning an enormous requested address range to completion.
- **Observed behavior:** The cancellation callback is reached, but search_decoy does not return within two seconds. The retained log prints PREPARED 16384 candidates and FAIL: search has not returned two seconds after its callback returned Cancelled. Exit 1; bounded probe total 13.54 seconds. Source shows stop is checked only before compare(index). find_address has no stop check inside the account/chain/index loops; thread::scope waits for that comparison to finish before the outer error can return.
- **Impact:** The documented native cancellation mechanism cannot interrupt a long address comparison. With allowed 2^31-index scopes a caller remains blocked and CPU work continues until the comparison completes or the process is terminated. The browser host can separately terminate its worker; that behavior was not classified under this finding.
- **Evidence:** [local-only core-cancel.log](AUD-016-evidence/core-cancel.log); [local-only core-cancel.command.json](AUD-016-evidence/core-cancel.command.json); [AUD-016-harnesses/core/public_probe.rs ](AUD-016-harnesses/core/public_probe.rs); [AUD-016-harnesses/core/cancel_watchdog.py ](AUD-016-harnesses/core/cancel_watchdog.py); [src/search.rs:284](../../src/search.rs); [src/search.rs:289](../../src/search.rs); [src/search.rs:309](../../src/search.rs); [src/wallet.rs:971](../../src/wallet.rs).
- **Recommended fix:** Pass a narrow cancellation predicate or callback into the library address-search loop and check it between derived addresses. The threaded candidate coordinator should set it on the first callback error and stop reporting repeatedly after that error; reuse the same address-search implementation across callers.
- **Required verification:** The bounded watchdog exits 0 after cancellation at a huge valid scope. Add a deterministic native regression that waits until a comparison starts, cancels, and confirms prompt joining. Preserve address vector outputs and normal default-scope search behavior; verify the browser and CLI integration when cancellation is threaded through the shared library.
