### Findings

#### AUD-052-SEC001 — Medium — Terminal write failure can deadlock panic cleanup

- Evidence. `src/bin/mhfe/scroll.rs:129`, `src/bin/mhfe/terminal.rs:414`, `src/bin/mhfe/startup.rs:162`, `src/bin/mhfe/hidden_input.rs:188`.
- Observed. anstream 1.0.0 panics on stderr write errors other than BrokenPipe. Private rendering and final cancellation can invoke it while holding DRAWING. The synchronous installed panic hook calls restore_and_exit, which blocks acquiring the same guard before unwind or abort can release it.
- Impact. An ordinary terminal or diagnostic I/O error can prevent cancellation or leave terminal recovery incomplete. Static control flow independently confirmed. The previous screen-transition race is fixed and the failure mode here is distinct.
- Recommended fix. Make all writes in the guarded rendering and cancellation paths fallible and prevent panic cleanup from blocking on a guard the panicking thread already holds.

#### AUD-052-SEC002 — Low — Other invalid inherited Windows handles can reach File::from_raw_handle

- Evidence. `src/bin/mhfe/raw_io.rs:130`, `src/bin/mhfe/raw_io.rs:211`.
- Observed. GetStdHandle may return other unvalidated values from the standard handle table. The failed GetConsoleMode branch constructs a File after checking two sentinels. The Rust constructor requires an open handle.
- Impact. A non-sentinel invalid handle can still violate the unsafe precondition. Both named sentinel cases now pass exact Windows tests. No runtime corruption was demonstrated.
- Recommended fix. Use non-owning Win32 reads with checked results and preserve EOF semantics, or obtain a validated handle with an appropriate ownership contract.

#### AUD-052-BLD001 — Low — Manual packaging fails with the system Bash on macOS

- Evidence. `scripts/package-release.sh:201`.
- Observed. The new manifest step uses mapfile, a Bash 4 builtin. macOS system Bash is 3.2. The script implements Darwin packaging and documents GNU archive tools but has no equivalent Bash version check.
- Impact. A supported manual packaging invocation on a Mac can write archives and then stop before writing a checksum manifest. The canonical Ubuntu build passes.
- Recommended fix. Collect the sorted names using a Bash-3-compatible read loop or explicitly require a newer Bash and check it before producing files.

#### AUD-052-DOC001 — Low — The documented release verification block can return success after a failed archive

- Evidence. `docs/RELEASING.md:49`.
- Observed. The shell snippet runs the hash check separately and loops over archive attestations without fail-fast or aggregated failure status.
- Impact. A copy-pasted automated check can report the final iteration's status even when an earlier archive verification failed. Explicit maintainers reviewing output can still notice the failure.
- Recommended fix. Make hash, source and every archive verification fail closed before any signing steps.

#### AUD-052-DOC002 — Low — Unix terminal documentation overstates cancellation and input cleanup

- Evidence. `docs/releases/unreleased.md:69`, `SECURITY.md:37`, `src/bin/mhfe/hidden_input.rs:799`, `src/bin/mhfe/terminal.rs:418`.
- Observed. Terminal mode restoration no longer waits for output, but synchronous screen or diagnostic writes can still wait. Input that arrives between input flush and mode restoration can go to the next reader, as the implementation comment states.
- Impact. The public guarantees of immediate completion and no carryover from a remaining paste exceed the properties established by the new mode cleanup.
- Recommended fix. Describe non-draining mode restoration, and state the limits for synchronous terminal output and bytes arriving after the flush.

#### AUD-052-DOC003 — Low — Release notes give the wrong public error for onNoLength

- Evidence. `docs/releases/unreleased.md:93`, `docs/BROWSER-PACKAGE.md:217`.
- Observed. The draft describes a TypeError as the rejected operation's public outcome. Exact browser logs and the browser guide show CALLBACK_FAILED with TypeError as its cause.
- Impact. An integrator following the release note can handle the wrong error type.
- Recommended fix. Describe CALLBACK_FAILED and its cause consistently with the browser guide.

#### AUD-052-API001 — Low — Positive wallet-check evidence bypasses the documented no-length callback

- Evidence. `web/core-worker.js:90`, `web/client.d.ts:532`, `docs/BROWSER-PACKAGE.md:210`.
- Observed. When detection finds no length, a positive 16-bit wallet check can cause the worker to return before calling onNoLength even when there is no verified match. The callback contract describes detection finding no length as the condition.
- Impact. A caller may wait for the opportunity to supply a stronger address or fingerprint reference that the worker never requests. The result itself remains unverified.
- Recommended fix. Follow the no-length callback contract for that path or explicitly document the intended exception and preserve the unverified outcome.
