### Findings

#### AUD-009-API001 - Medium - Worker creation failure leaves the operation pending

- **Category:** API.
- **Status:** open.
- **Release blocking:** true; Supported browser API contract failure should be fixed before publishing this refactor.
- **Affected files/builds:** web/runtime.js:91; browser API.
- **Reproduction:** Make URL.createObjectURL throw a synthetic error, then run WorkerJob with a valid compiled module and synthetic password bytes.
- **Expected:** Reject with WORKER_FAILED, release the operation slot and wipe owned byte copies.
- **Observed:** The run promise remains pending, ended is false, an unhandled rejection occurs and the bytes remain nonzero.
- **Impact and limits:** A browser refusing Blob URLs can leave a long-operation slot permanently busy and retain its byte copies.
- **Evidence:** In-memory synthetic Node probe; browser-boundaries harness or module namespace inspection.
- **Recommended fix:** Wrap Blob creation, URL creation and startup in one failure boundary; stop and wipe on every exception.
- **Required verification:** Inject Blob/URL/Worker failures and assert settled rejection, released slot and zeroed client copies.

#### AUD-009-API002 - Medium - Wallet progress drops asynchronous callback failures

- **Category:** API.
- **Status:** open.
- **Release blocking:** true; Supported browser API contract failure should be fixed before publishing this refactor.
- **Affected files/builds:** web/wallet.js:145; browser API.
- **Reproduction:** Emit a draws message while onProgress returns a rejected Promise.
- **Expected:** Reject the drawing operation with CALLBACK_FAILED and terminate its workers.
- **Observed:** The wrapper does not return the callback Promise; rejection is unhandled and the drawing operation and worker continue.
- **Impact and limits:** The documented callback-failure contract fails during checked phrase generation.
- **Evidence:** In-memory synthetic Node probe; browser-boundaries harness or module namespace inspection.
- **Recommended fix:** Return the callback result so WorkerJob.callPage observes its rejection.
- **Required verification:** Assert asynchronous rejection cancels all drawing workers and rejects with CALLBACK_FAILED.

#### AUD-009-API003 - Medium - Declaration error exports are missing from runtime modules

- **Category:** API.
- **Status:** open.
- **Release blocking:** true; Supported browser API contract failure should be fixed before publishing this refactor.
- **Affected files/builds:** web/passwords.d.ts:2; web/repair.d.ts:2; web/wallet.d.ts:2; browser API.
- **Reproduction:** Import MhfeError from passwords.js or repair.js, or either error class from wallet.js.
- **Expected:** Named value exports promised by declarations exist in the JavaScript modules.
- **Observed:** Actual module namespaces contain only their main class; the named imports fail module linking.
- **Impact and limits:** TypeScript-valid consumers fail at runtime before calling any operation.
- **Evidence:** In-memory synthetic Node probe; browser-boundaries harness or module namespace inspection.
- **Recommended fix:** Add matching JavaScript value reexports or remove the unsupported declaration exports.
- **Required verification:** Compare declaration value exports with actual ES-module namespaces and exercise named imports.

#### AUD-009-API004 - Medium - Word-index generation accepts a character recipe and returns an empty password

- **Category:** API.
- **Status:** open.
- **Release blocking:** false; Bounded native API or lifecycle defect; no current frontend compromise demonstrated.
- **Affected files/builds:** src/new_password.rs:139; native public library API.
- **Reproduction:** PasswordRecipe::characters(16).unwrap().make_from_indexes(&mut |_| Ok(0)).unwrap().
- **Expected:** Reject a character recipe at this word-generation entry point.
- **Observed:** Source trace: drawn_words is zero, no callback runs, and success returns empty text with a 93328-millibit recipe marked not weak.
- **Impact and limits:** Native library consumers can receive an empty password accompanied by strong-generation metadata. Current CLI/WASM dispatch does not call this invalid combination.
- **Evidence:** Direct source trace, not an executed native reproduction.
- **Recommended fix:** Reject character recipes here, as make_from_rolls already does, or separate word-recipe types.
- **Required verification:** Run a negative public-API regression asserting character recipes cannot produce successful empty text.

#### AUD-009-API005 - Medium - Rekey guards declared settings while encrypting with independent engine settings

- **Category:** API.
- **Status:** open.
- **Release blocking:** false; Bounded native API or lifecycle defect; no current frontend compromise demonstrated.
- **Affected files/builds:** src/rekey.rs:132; native public library API.
- **Reproduction:** Recover an old container at settings A/password P; seal with an Mhfe configured at A and password P but declare new_work B different from A.
- **Expected:** Reject settings mismatch or use the engine's authoritative settings; unchanged rekey must be refused.
- **Observed:** Source trace: check_new compares B with stored A, while Encryption runs at the supplied engine's A; deterministic output is the old container.
- **Impact and limits:** Native consumers can bypass the unchanged guard and attach recovery instructions for settings different from those used. CLI/WASM construct matching engines in reviewed paths.
- **Evidence:** Direct source trace, not an executed native reproduction.
- **Recommended fix:** Use mhfe.work_factor() as authoritative or reject mismatches in recover/seal before work.
- **Required verification:** Exercise old and new engine/declaration mismatches and unchanged-output prevention with a reduced-cost test engine.

#### AUD-009-SEC001 - Low - Invalid repetition arguments leave earlier secret byte copies unwiped

- **Category:** SEC.
- **Status:** open.
- **Release blocking:** false; Bounded native API or lifecycle defect; no current frontend compromise demonstrated.
- **Affected files/builds:** web/passwords.js:59; web/wallet.js:122; browser API.
- **Reproduction:** Use a synthetic nonempty first password/passphrase and an invalid repetition argument (number or lone surrogate); instrument TextEncoder to observe owned arrays without printing contents.
- **Expected:** Every client-owned temporary secret buffer is wiped when validation rejects.
- **Observed:** The first encodeSecret succeeds; the repetition encoder throws before any cleanup guard, leaving the first array nonzero.
- **Impact and limits:** Bounded secret-lifetime regression on invalid-input paths; no persistence, network exfiltration or user-secret compromise demonstrated.
- **Evidence:** In-memory synthetic Node probe; browser-boundaries harness or module namespace inspection.
- **Recommended fix:** Use cleanup guards around staged secret encoding, following the core client's existing pattern.
- **Required verification:** Assert rejection wipes all allocated temporary arrays for invalid repeat types/text while preserving caller arrays.

### Informational observations and recommendations

- One shared WASM, one worker and independent module classes is a coherent implementation of the requested modularity. Cargo flags preserve selective binding builds.
- CLI encryption/new/rekey now use the common library Encryption operation, removing meaningful duplication.
- `src/wasm_api/mod.rs:1-3` retains the old per-module-WASM description; update that internal comment when remediating.
- Deriver currently retains the older embedded package/API counter; handover and actual browser fields/operations remain a separate integration gap. No Deriver source edits were part of this audit.
- The API leaves owner confirmation and caller-supplied recovered phrase provenance to the host. Stronger typed state could reduce misuse; this is an optional improvement, not an additional confirmed defect.
- Password generation error paths declare the temporary lock guard after its wiping buffer; reverse local drop order can unlock before wipe. No leak reproduced; review drop ordering as a separate bounded hardening task.
