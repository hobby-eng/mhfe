### Scope and methodology

The review traced suites 3/4 from phrase reading and packing through the native and browser engine boundaries, Feistel round messages, work settings and recovery, then examined new-wallet selection, independent BIP39 passphrases, wallet-identity checks, rekey, terminal visibility, memory ownership, local serving and build/workflow source. Agent reasoning is review evidence, not an independent certification.

Native C Argon2 context parameters, key/mask length, BLAKE2b digest size and error cleanup were source-reviewed. No demonstrated mismatch was found in the normative suites 3/4 cryptographic core. Reduced-cost tests and structure checks support this conclusion; they do not reproduce full-cost Argon2 or prove the conjectured cost of every attack.

The optional seed check is a draft new-wallet generation profile. The current implementation uses a nonempty BIP39 passphrase and 24-word generation. It retains ordinary BIP39 encoding and seed derivation, but its rejection-selected distribution requires explicit entropy/security qualifications. BIP39/BIP32 were checked separately: no explicit rejection-sampling prohibition was found; this is format interoperability, not a standards endorsement of the new security profile.

#### AUD-007-SEC001 — Medium — Private-display paths write source mnemonics to redirected stdout

- **Category:** SEC.
- **Severity:** medium.
- **Status:** verified (open at the reviewed commit; see Remediation and follow-up).
- **Release blocking:** true; resolve this supported safety/interoperability contract before accepting the affected feature for release.
- **Affected files and builds:** `src/bin/mhfe/terminal.rs:341`, `src/bin/mhfe/new_wallet.rs:252`, `src/bin/mhfe/wallets.rs:128`, `src/bin/mhfe/rekey.rs:216` at the reviewed snapshot.

### Informational observations and recommendations

The implementation consistently treats the 16-bit seed check as different from an independent wallet-identity reference in the operative `check`/rekey result paths. Correct those source comments and supplementary claims that overstate this behavior. Keep the independent strong BIP39 passphrase recommendation; this report does not recommend dropping that second secret.

For 16 versus 20 bits, the modeled accidental-match probability changes from 1/65,536 to 1/1,048,576 and expected creation work grows sixteenfold. With fixed passphrase the conditional entropy of a 24-word generated source is approximately 240 versus 236 bits. Neither value turns the check into authentication or a unique wallet identifier. The measured single creation time is not a promised completion time.

Before a release, remediate supported-flow blockers and execute the omitted canonical builds, full vectors, browser acceptance, platform checks and artifact provenance verification against a single final snapshot. Source-only review of workflow definitions is not evidence that remote jobs ran.
