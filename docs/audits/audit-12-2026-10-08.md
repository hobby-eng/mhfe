### Findings

#### AUD-012-SEC001 - Low - Phrase drawing setup failures bypass owned passphrase cleanup

- **Category:** SEC
- **Severity:** low
- **Status:** open
- **Release blocking:** false; Bounded local API/tooling defect; no exploitable disclosure, wrong cryptographic output or mandatory release gate failure demonstrated.
- **Affected files and builds:** web/wallet.js:127, web/wallet.js:138, web/wallet.js:161, web/wallet.js:195
- **Reproduction:** Call unchanged MhfeWallet.drawPhrase with synthetic matching passphrase, walletCheck:true and workers:2**32. Probe observes exactly two copies and asserts wipe after rejection.
- **Expected behavior:** All package-owned passphrase copies are wiped on refused preparation; partial workers/slot ownership are cleaned on failure.
- **Observed behavior:** Positive safe integer 2**32 is accepted. Two passphrase copies are encoded, then new Array(count) immediately throws RangeError before normal-path fill(0).
- **Impact:** Local owned-buffer residual lifetime on host-invalid options. No enormous allocation, worker creation, network disclosure, memory persistence beyond GC or theft demonstrated.
- **Evidence:** browser/draw-refusal.mjs exits 1; independently reproduced by browser reviewer and challenged by CLI/docs skeptic.
- **Recommended fix:** Bound worker-count inputs before encoding and protect all drawing setup allocations/copies/start calls with finally cleanup. On partial setup failure stop started workers and release the operation slot.
- **Required verification:** Invalid count, array allocation, first/second per-worker copy and worker-start failures wipe all owned copies, preserve caller buffers, stop partial jobs and permit subsequent drawing.
- **Related historical findings:** AUD-009-SEC001, AUD-011-SEC001

#### AUD-012-SEC002 - Low - Recovered result exposes a relocatable secret buffer outside its lock owner

- **Category:** SEC
- **Severity:** low
- **Status:** open
- **Release blocking:** false; Bounded local API/tooling defect; no exploitable disclosure, wrong cryptographic output or mandatory release gate failure demonstrated.
- **Affected files and builds:** src/mhfe.rs:77, src/mhfe.rs:128, src/memory.rs:209, SECURITY.md:49
- **Reproduction:** Compile rust/public-mutation.rs against freshly checked libmhfe.rlib. Its safe external function reserves extra capacity and appends synthetic text through the public field; inspect the immutable guard range and no RecoveredPhrase mutation precondition.
- **Expected behavior:** The library-owned recovered text cannot grow or relocate while a private guard protects its original allocation.
- **Observed behavior:** RecoveredPhrase::phrase is a public mutable Zeroizing<String>. Its constructor splits LockedText into that string and a private LockedPages guard whose start/bytes never follow String growth or replacement. Safe external reserve/push_str compiles.
- **Impact:** Unenforced API secret-lifetime invariant and possible unlocked replacement storage when a native caller mutates a recovered result. Current CLI/browser callers were not shown doing this. No runtime swap/freed-memory disclosure measured; relocation/free concerns follow from ownership source, not a captured secret.
- **Evidence:** public-mutation-current compiles exit 0; coordinator source trace plus independent Rust ownership challenge. Compile-only witness, not actual recovery/swap test.
- **Recommended fix:** Keep the owned phrase as private LockedText and expose a read-only phrase accessor. Update front ends/types/docs consistently; consider read-only factual metadata to retain result invariants.
- **Required verification:** External compile-fail regression prevents grow/replace mutation, normal read/consume paths still work, and native lock/zeroize tests confirm locked allocation lifetime.
- **Related historical findings:** AUD-010-SEC002

- **Severity:** low
- **Status:** open
