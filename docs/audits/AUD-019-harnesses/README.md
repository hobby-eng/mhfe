# AUD-019 harnesses

Time zone: UTC (+00:00)

Privacy-only documentation update: this is not a new audit. No checks were rerun; recorded results and evidence are unchanged.

These harnesses belong to the final full-scope audit of MHFE v0.6.0 at signed commit `66f142566464255e331763966b00ea1681c2dabd`. The report is `../AUD-019-2026-10-11.md`, with a JSON companion. They use only public vectors and synthetic inputs. They do not modify product source, publish a release or repeat the full-cost vectors.

Run from the authoritative MHFE checkout with the workspace toolchains: Rust/Cargo 1.99.0, wasm-bindgen 0.2.129, Node 26.10.0 and Docker. Set `CARGO_HOME=/home/user/Documents/bip_tools/workingspace/cargo` and `RUSTUP_HOME=/home/user/Documents/bip_tools/workingspace/rustup` to the corresponding runtime locations. Home paths in this README are anonymized; executable tools resolve their real checkout paths themselves.

- `run.py LABEL COMMAND [ARGS...]` imports the immutable AUD-016 command runner and writes current logs, exact arguments, environment, UTC times, exit code and SHA-256 to ignored `../AUD-019-evidence/`. `run.py snapshot LABEL` hashes both authoritative repositories, excluding this audit's own records. Its process-group RSS applies to observed command processes, not automatically to Docker daemon children.
- `artifacts.py` requires the retained `canonical-output-signing-v0.6.0/`, `canonical-output-v0.6.0/release/`, current `dist/`, current host package and captured Release publish log. It checks all six candidate hashes, source/build metadata, licenses, archive framing and browser bindings. It extracts only the known regular Linux executable into ignored evidence. Expected result: six archive checks and four local canonical matches; pending OpenPGP signature is reported explicitly.
- `prepare-verifier.py` requires the official GitHub CLI v2.101.0 Linux archive and its official checksum list in the ignored evidence tool directory. It verifies the SHA-256 and extracts only the known regular `gh` executable into that directory. This is an audit-local verifier bootstrap through official HTTPS/checksums, not a separately authenticated signature on the verifier download.
- `supply-chain.py` imports the retained AUD-018 implementation, checks exact Cargo/npm archives and installed files, and preserves the implementation's origin alongside the current audit ID. It needs the configured Cargo cache, `node_modules/`, lockfiles and access to the three public npm archives. Expected result: no integrity mismatches.
- `canonical.py` refuses tracked changes and any untracked file outside this audit, then invokes the repository's canonical recipe through the retained AUD-018 cgroup wrapper with `REPRODUCIBLE_NO_CACHE=1`. Only the new audit documents are excluded from process-local Git status; no Git configuration is changed on disk. It writes ignored `canonical-output-aud019_uncached/`. Run once under a systemd user unit with `MemoryMax=4294967296`, `MemorySwapMax=0`, `TasksMax=256`, `RuntimeMaxSec=1200` and the unit name in `MHFE_AUDIT_UNIT`. Add an `ExecStopPost` readback of `MemoryPeak`, `MemoryMax`, `MemorySwapMax` and `Result` before the unit is collected. Heavy checks must run one at a time across sessions.
- `compare-canonical.py` compares all four uncached archives and the four-target checksum file byte for byte with the retained canonical export, and each archive with the six-target release candidate. The six-target checksum file naturally differs in inventory. Expected result: four archive matches and an identical canonical checksum file; macOS reproduction is outside this local Docker recipe.
- `assemble.py` reads retained current evidence and reviewer records, anonymizes published paths and generates the standard Markdown/JSON pair. It does not execute product tests. It refuses to claim successful uncached reproduction without its successful command and comparison records.
- `validate.py` checks the schema, all 32 checklist IDs, original remediation IDs, pair consistency, privacy, command/log hashes, procedure hashes, source preservation and the evidence/harness bindings. Expected result: exit 0 and a local validation record. It validates evidence consistency, not a new cryptographic test of MHFE.

The [core](core/README.md), [native](native/README.md) and [browser](browser/README.md) READMEs document their distinct probes and limits. Existing harnesses are imported or invoked without changing their bytes. Initial harness/environment failures remain in evidence alongside corrected executions.
