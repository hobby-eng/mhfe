## Review evidence

### Scope and methodology

A full-scope review of the release commit with the shared 32-task procedure: the core formulas
re-derived from the suite 3 text and compared with the code, the unsafe FFI and work-area lifecycle,
every secret's path through library, CLI, WebAssembly and worker, the CLI and both fast-mode
launchers, the browser package in real browsers, builds, packaging, licences, dependencies, CI and
release workflows, and every document. Previous findings served as a regression checklist. Only
public fixtures and synthetic inputs were used. This is a first-party AI-assisted audit, not a
specialist certification.

Environment: Linux 7.0.0-34 x86-64, 16 threads, 15 GiB RAM; Rust/Cargo 1.98.1; wasm-bindgen 0.2.129;
Emscripten 6.0.10; Node 26.10.0; Python 3.14.4; cargo-audit 0.22.2; Prettier 3.9.9; Playwright from
multi-chain-wallet-tools with Chromium 153.0.8010.12 and Firefox 155.0. Cargo builds used one job.

Excluded by instruction: Docker and the reproducible build (the host's Docker was in use for other
repositories), full-size 2 GiB Argon2 runs, the full vector replay, and any remote change. The
macOS, Windows and canonical results quoted below are exact-commit CI runs read with `gh`; they are
external evidence, not local runs.

Evidence is kept locally in the ignored `docs/audits/AUD-005-evidence/` and is not part of the
repository; every command, result and log hash a reader needs is reproduced here and in the JSON
companion. The [harnesses](AUD-005-harnesses/README.md) are committed and explain reruns.

### Specification conformance

No discrepancy with suite 3 was found. Every rule below was read in the specification and traced to
the code; the outputs are pinned by the reduced-cost container, the 160 C/RustCrypto Argon2
cross-checks, the RFC 9106 vector, the fast validation cases (equal to the specification's bytes)
and 17 transcripts recomputed by the independent script with their recorded Argon2 keys. Full-cost
recomputation was excluded.

| Rule group        | Implementation and evidence                                                                                                                                                                                                                                                      |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Suite parameters  | `SUITE_ID`, `DS_SALT` and `DS_MASK` without NUL; 12 rounds; Argon2id 0x13, 4 lanes, 32-byte output, empty secret and associated data (`src/suite.rs`, `src/engine/native.rs`, `web/argon2-engine.js`).                                                                           |
| Password encoding | Cc, U+2028 and U+2029 refused before normalization; unassigned code points refused, private use accepted; NFKD with Unicode 17.0.0; 1 to 1024 bytes, never truncated; no case folding or trimming (`src/password.rs`).                                                           |
| Reading words     | Exact word first, then a unique prefix of at least four letters; any case and spacing; checksum required; error messages give positions, not words (`src/phrase.rs`).                                                                                                            |
| Packing           | `X = E \|\| Trunc_r(SHA-256(E))`, digest byte order, 24 words fill `X` alone (`src/packing.rs`).                                                                                                                                                                                 |
| Permutation       | `S_i` from BLAKE2b with a 32-byte output parameter, `K_i` from Argon2id, `M_i` from HMAC-SHA-256 keyed with `K_i`, messages `BE32(MEM) \|\| BE32(PIM) \|\| BE32(i) \|\| R`; forward rounds 0 to 11 and the inverse in reverse order (`src/feistel.rs`).                          |
| Work factor       | `m(MEM)` and `t(PIM)` with integers; ranges checked before allocation; native supports every level, the browser level 0 and refuses others first.                                                                                                                                |
| Creation          | Settings validated and memory checked before secrets; fixed point refused; words decoded again and inverted before release; the early display at a terminal is marked unverified and its outcome reported; scripts and redirected output get the container only after the check. |
| Recovery          | 24 words with a valid checksum before any Argon2 call; detection, manual lengths, ambiguity with every candidate plus the unverified 24-word reading; 24-word results always unverified; a verifier match is not described as wallet identity.                                   |
| Rehearsal         | Answers only matches or does not match; address and fingerprint checks include the BIP39 passphrase and every reading of `X`.                                                                                                                                                    |
| Application rules | Suite identifier, settings, memory and time shown before work; non-default settings must be remembered; offline guidance; no network code; cancellation at any moment by process or worker termination.                                                                          |

### Findings

#### AUD-005-SEC001 — Low — Phrase text is built in growing strings that leave unwiped copies in freed memory

- **Category:** SEC (Secret lifecycle).
- **Severity:** low.
- **Status:** open (see Remediation and follow-up).
- **Release blocking:** false. Best-effort memory hygiene on the user's own offline computer; no
  disclosure path to another party is demonstrated.
- **Affected files and builds:** `src/phrase.rs:71` (read_phrase); `src/mhfe.rs:257`
  (phrase_from_entropy, used by decrypt, the rehearsal check and encrypt); `src/bin/mhfe/encrypt.rs`
  (reads the original through read_phrase).
- **Reproduction:** cargo run --offline --manifest-path
  docs/audits/AUD-005-harnesses/phrase-copies/Cargo.toml --target-dir target/aud005-phrase-copies.
  The probe installs a global allocator that, whenever a block is freed or moved by a reallocation,
  looks for the text "legal winner" in the old bytes, then calls the public mhfe::read_phrase with
  the public BIP39 phrase "legal winner thank year ..." typed in short upper-case forms.
- **Expected behavior:** SECURITY.md and API.md: every buffer the crate owns that holds a phrase is
  wiped when dropped; only working buffers inside dependencies are excepted. The crate already
  reserves its other phrase and password buffers at full size for exactly this reason
  (phrase::parse, Password::new, the terminal readers).
- **Observed behavior:** 4 freed heap blocks still held the phrase after read_phrase returned.
  Mnemonic::to_string writes word by word into an empty String, which grows 8, 16, 32, 64, 128 and
  256 bytes; every growth frees the previous block unwiped. Only the final buffer is wiped by
  Zeroizing. phrase_from_entropy, which turns every recovered state into text, has the same pattern
  by source inspection.
- **Impact:** Prefixes of an original or recovered phrase can remain in freed heap memory of the
  process until it is reused or the process ends, where a memory dump, swap or a later
  memory-disclosure bug could find them. The process is short-lived and runs offline, and the
  operating system discards the memory at exit, so the practical risk is small; the defect is the
  gap between the documented guarantee and the code.
- **Evidence:** local AUD-005-evidence/phrase-copies.log; harness
  docs/audits/AUD-005-harnesses/phrase-copies/
- **Recommended fix:** Build phrase text in a Zeroizing<String> reserved at its final size (word
  count times nine bytes) from Mnemonic::words, as phrase::parse already does, and use it in
  read_phrase and phrase_from_entropy. Containers are not secret and may keep to_string.
- **Required verification:** The allocator probe reports 0 copies for read_phrase; a unit test shows
  that the buffer is never reallocated for every phrase length; the native suite and the
  reduced-cost container tests still pass, proving unchanged outputs.
- **Procedure checks:** CHECK-SEC-001, CHECK-SEC-005.

#### AUD-005-FUN001 — Low — The weak-password warning counts a repeated dice word as several words

- **Category:** FUN (Password advice).
- **Severity:** low.
- **Status:** open (see Remediation and follow-up).
- **Release blocking:** false. Advisory heuristic only; the password is still encoded and used
  exactly as typed.
- **Affected files and builds:** `src/bin/mhfe/diceware.rs:203` (dice_word_count);
  `src/bin/mhfe/encrypt.rs:359`.
- **Reproduction:** python3 docs/audits/AUD-005-harnesses/cli-probes.py. It runs mhfe encrypt
  --stdin with the public phrase "abandon ... about" and a password typed twice, under a 1 GiB
  address-space limit, so the tool stops with exit code 4 when it tries to reserve the 2 GiB work
  area, after it has judged the password and before any Argon2 work.
- **Expected behavior:** The specification asks applications to recommend at least four words chosen
  with dice and to warn about weak passwords; the warning text says the password is not four or more
  words from the EFF dice list. "abacus abacus abacus abacus" is one dice word, about 12.9 bits.
- **Observed behavior:** "abacus" gets the warning, but "abacus abacus abacus abacus" passes without
  it: dice_word_count counts every token that is an EFF word, including repeats.
- **Impact:** A person who repeats one word, or a few words, is told nothing, although such a
  password is far weaker than four independent dice words. Containers and outputs are unaffected.
- **Evidence:** local AUD-005-evidence/cli-probes.log and cli-probes-2.log
- **Recommended fix:** Count the different EFF words of a password made only of EFF words and warn
  below four, saying different words; compare case-insensitively without allocating copies of the
  password.
- **Required verification:** The probe expectation passes; unit tests cover repeats, case and
  non-list words; the documented warning wording matches.
- **Procedure checks:** CHECK-UI-003.

#### AUD-005-UI001 — Low — A failed memory reservation or a processor refusal recommends a memory level

- **Category:** UI (Resource messages).
- **Severity:** low.
- **Status:** open (see Remediation and follow-up).
- **Release blocking:** false. The refusal itself is correct and happens before any Argon2 work;
  only the added advice is wrong.
- **Affected files and builds:** `src/bin/mhfe/settings.rs:144` (with_level_hint).
- **Reproduction:** python3 docs/audits/AUD-005-harnesses/cli-probes.py (allocation part): mhfe
  encrypt --stdin at memory level 0 under a 1 GiB address-space limit. A processor refusal of the
  SSSE3 build goes through the same function (source trace; no processor without SSSE3 was
  available).
- **Expected behavior:** Advice should follow from the failure: a lower level helps when the
  computer reports too little free memory, not when a reservation the report allowed has just
  failed, and never for a missing processor feature.
- **Observed behavior:** "The computer could not reserve 2 GiB of memory for Argon2. The highest
  memory level this computer can use now is 3." Level 3 needs 6 GiB, three times what just failed.
  with_level_hint appends this sentence to every resource error, including ProcessorNotSupported.
- **Impact:** Misleading advice in a rare failure: a user may retry, or worse, choose a higher
  memory level for a new container, and then need a computer with that memory for every recovery. No
  secret or output is affected.
- **Evidence:** local AUD-005-evidence/cli-probes-2.log
- **Recommended fix:** Append the level hint only to NotEnoughMemory, the refusal that is based on
  the reported free memory.
- **Required verification:** The probe expectation passes; a unit test checks that allocation and
  processor refusals carry no level hint and that a memory refusal still can.
- **Procedure checks:** CHECK-UI-003, CHECK-SEC-007.

### Informational observations and recommendations

- The browser client throws synchronously for argument and state errors (TypeError, INVALID_PIM,
  BUSY, PASSWORDS_DIFFER, INVALID_PASSWORD_TEXT) from methods typed as returning a Promise, and
  rejects only for worker errors. await handles both, a bare .catch() does not. This is
  long-standing, tested behaviour that the wallet tools may rely on, so it is left as a decision for
  the owner rather than a finding.
- Carried from AUD-004: exceptions thrown by the page's onProgress or onUnverified callbacks
  propagate to the page's event loop and do not stop the operation; documenting this or turning it
  into a rejection is still open.
- No Prettier configuration exists in this repository; with the mhfe_spec configuration 12 Markdown
  and JavaScript files differ (mostly prose wrapping and quote style). Files touched by the
  remediation were formatted; the rest were left as they are.
- scripts/independent-suite3.py takes NFKD from Python's unicodedata, Unicode 16.0.0 on Python 3.14,
  and does not apply the Unicode 17.0.0 unassigned-code-point rule. This does not affect the public
  corpus, whose passwords use long-assigned characters, but the script is not an independent check
  of that rule.
- Workflow hardening, not defects: vectors.yml installs cryptography==46.0.5 without a hash; the
  release canonical job checks out with persisted credentials (.git is excluded from the Docker
  context); the publish job writes SHA256SUMS over the downloaded artifacts without comparing them
  with the canonical job's own SHA256SUMS.
- Carried from AUD-004: Linux MemAvailable is not cgroup-aware, and the macOS memory query does not
  release its Mach host port.
- scripts/build-reproducible.sh sends the whole working tree minus .dockerignore to Docker,
  including untracked and ignored local files such as audit evidence and **pycache**. They do not
  reach the archives, which are built from named files, and CI builds from a clean checkout; a local
  canonical build of a modified tree is still labelled with the package version only.
- When standard error is redirected but standard output is a terminal, mhfe encrypt shows the
  container before its check while the not-verified notice goes to the redirected stream. Prompts go
  there too, so this needs a deliberately unusual invocation.
- Release run 36823878528 for v0.4.0 had its canonical and macOS jobs finished successfully and the
  full-size vector replay still running when it was read; no published release asset was compared.

### Assessment and limitations

Seven low findings and no critical, high or medium one. No suite 3 mismatch, secret exfiltration
path, wrong recovered phrase or broken integrity gate was found in the reviewed paths. The findings
are a memory-hygiene gap behind a documented guarantee, two misleading CLI messages, and four
documentation and record defects. This is the evidence of this audit, not proof that no other defect
exists.

- No full-cost 2 GiB Argon2 execution, full positive or negative vector replay, or new vector
  generation (excluded by instruction). Recorded-key transcript checks do not recompute Argon2.
- No Docker or reproducible build; canonical byte equality rests on exact-commit CI jobs, which are
  external evidence.
- No local macOS, Windows, ARM64, Safari or mobile execution; Windows PE and the Windows binary's
  DLL imports were not inspected.
- No independent cryptographic proof, side-channel measurement or review of dependency internals
  beyond their integration.
- The phrase-copy probe observes the Rust heap of one process; it does not cover copies made by the
  operating system, the terminal or the standard library's input buffer, which SECURITY.md already
  names.
- The processor-refusal half of AUD-005-UI001 is established by source trace, not by running on a
  processor without SSSE3.
- No real wallet material was used; only the public phrases "abandon ... about" and "legal winner
  ...", the public test passwords and synthetic EFF words.
