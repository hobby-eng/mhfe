## Review evidence

### Scope and methodology

Ordinary full-scope audit (compact team, workspace AGENTS.md 'Audit depth') of the uncommitted modular refactor on d7af4b1035355a69779f8ad70a9dc50ba5b9ffd0: Rust library, command-line tool, single-WASM bindings, the browser package (web/ and the local dist/ build), build and release scripts and workflows, documentation and audit records; verification of the six AUD-009 findings. Not release acceptance.

A coverage planner assigned all 32 CHECK-* items of FULL_AUDIT_GUIDE.md; five reviewers worked in parallel on distinct scopes with source traces bound to file hashes, independent oracles written for the audit, production-source probes, pseudo-terminal probes and the shared check.sh and real-browser runs; each reviewer's findings went to a separate challenger who reproduced or re-derived them and confirmed, downgraded or refuted each one. All 24 findings were confirmed (one downgraded); none was refuted. Only public test vectors and synthetic secrets were used; reviewers edited no production, test, fixture, documentation or script file.

Excluded:

- Canonical Docker rebuild and release archives; paid GitHub Actions runs.
- Argon2 above 256 MiB in the reviewers' work; full-size runs only in the coordinator's capped chain, one at a time.
- Cross-target compilation and runtime (aarch64-linux, windows-gnu, windows-msvc, macOS).
- Upstream dependency internals and an independent cryptographic proof.
- mhfe_spec and multi-chain-wallet-tools were read, not audited.

Environment: Linux 7.0.0-38-generic x86_64, 16 CPUs, 15.4 GB memory; rustc and Cargo 1.99.0, wasm-bindgen 0.2.129, Node 26.10.0, Python 3.14.4, Emscripten 6.0.10, Playwright 1.63.0 with Chromium 153.0.8010.12 and Firefox 155.0, cargo audit 0.22.2 with the local advisory database at ef6173cb (2026-10-03) (local-only environment.log and the reviewers' logs).

#### AUD-010-SEC001 — Low — Phrases passed to the WebAssembly bindings as text stay unwiped in linear memory

- **Category:** SEC (Security).
- **Severity:** low.
- **Status:** verified since the remediation follow-up of 2026-10-07; open at the reviewed snapshot (see [Remediation and follow-up](#remediation-and-follow-up)).
- **Release blocking:** false; bounded documented-guarantee defect: the package's classes terminate the worker after each operation and the page already holds the phrase as an immutable JavaScript string.
- **Reviewer scope:** secrets-security.
- **Affected files and builds:** src/wasm_api/core.rs:119 (describePhrase, phrase: &str) and :264-265 (encrypt, phrase: &str); src/wasm_api/wallet.rs:52 (walletCheck) and :61 (walletFingerprint); Claims at src/wasm_api/mod.rs:12-15, docs/API.md:249-252 and docs/API.md:709-710; Browser build dist/runtime/mhfe.wasm (SHA-256 23b1fcecec69c077602ac40355676f243de0889c29ff0b7232e8dc24adb3a29b) and any program that uses the bindings directly.

- **Expected behavior:** Per src/wasm_api/mod.rs ('Secrets arrive as UTF-8 bytes and are wiped here after use') and docs/API.md:249 ('Every buffer and binding this crate owns that holds a password, phrase, ... is wiped when dropped'), no copy of a phrase stays in the module's memory once a binding returns, as is already the case for password and passphrase bytes, secret results and session secrets.

- **Required verification:** Rerun wasm-residue.mjs: the W3 cases leave 0 copies (or the documentation records the limit and the probe classifies them as documented); scripts/verify-browser-package.mjs and scripts/verify-browsers.mjs pass; client-lifecycle.mjs still passes with phrases in the transfer list.
- **Challenge:** confirmed, low. Reproduced with a byte-identical log (same three W3 failures, 23 passes) on the same input hashes. The needle is the capitalized, double-spaced typed form, which phrase::parse never copies whole, so the surviving copy can only be the binding's argument buffer. The claims at src/wasm_api/mod.rs:12-13 and docs/API.md are false for phrase inputs. Low, not medium: the workers already hold the phrase as a JavaScript string with the same lifetime, and docs/BROWSER-PACKAGE.md does not claim phrase inputs are wiped. The affected list is complete.

Low, consistent with AUD-008-SEC003 and AUD-007-SEC003 (AUD-007-SEC002 was medium because the mechanism itself undid successful locks). Not release blocking; the smaps verification is feasible, as AUD-008 showed.

### Informational observations and recommendations

No finding was refuted, so no finding became an observation. The following observations carry no finding IDs; recommendations are optional improvements, not confirmed defects.

crypto-core:

- AUD-009-API005 residual hardening: Sealed::keep(work, passphrase) (src/operation.rs:250) takes the work factor from the caller instead of recording the one the container was sealed with; every current caller passes the engine's own value.
- Bitcoin and Litecoin '3…' addresses are read as P2SH-P2WPKH (documented in src/wallet.rs); a multisig P2SH address cannot be told apart and ends as 'does not match' rather than a refusal. Inherent to the encoding.
- Provenance: tests/fixtures/suite3-vectors/independent-verification.json names verifier SHA-256 25d578ee… while scripts/independent-suite3.py is now bcc12b46…; every recorded fixture hash equals the current file. The suite 4 record matches its script.
- Shared ancestry: scripts/independent-suite3.py and -suite4.py come from the same project as the Rust code. oracle.py was written for this audit from the specification and standards and imports nothing from the repository; Argon2id in both Python oracles is OpenSSL's. Third-party values used as oracles: BIP39 english.txt, the trezor vectors of the bip39 3.0.0 crate, BIP32 vectors 1 and 3, RFC 9106, FIPS 180-4, RFC 4231, BIP173/BIP350, the CashAddr example and DIP-0017/DIP-0018 (dashpay/dips, read 2026-10-07).
- DIP-0018's testnet strings encode the HASH160 of the mainnet-path keys; tdash addresses are searched under coin type 1 as DIP-0017 prescribes, so those strings are found only at the given mainnet path. Consistent with the DIPs.
- Repair beyond the bound: in 300 random patterns with 2e+s > k the library refused every one (REPAIR_NOT_POSSIBLE), as an independent decoder plus the BIP39 checksum predicts; no mis-repair in this sample.
- The startup address self-check derives each table address with master.derive and program_for; find_address runs only in the full tier (two searches, none with DIP-0017's hardened key classes). The search loop is covered by unit tests and this audit's probe, not by the self-check.
- validation_cases::suite_4_refusals_come_before_argon2 accepts any of three refusal kinds for every case while the fixture records only 'rejected'; 25 bare is_err() assertions remain (local-only crypto-core-grep-markers.log).
- Comment nit: root_pattern's example "{44,49,84,86}'/0'" in src/wallet.rs cannot occur, since search_roots gives one purpose per address type.

secrets-security:

- After walletCheck, the bip39 crate's PBKDF2 salt block leaves two copies of the passphrase in linear memory, within the documented dependency limit (docs/API.md:250-252, SECURITY.md:35-37). Recommendation: enable the existing 'zeroize' features of hmac 0.13, sha2 0.11 and blake2 0.11, which adds no crate.
- Worker-side JavaScript copies of session secrets (hidden-wallet main passphrase; rekey passwords and passphrase) stay in the worker's request object until the session ends; the 'answer' branch of web/worker-runtime.js returns without wiping when no question is pending (unreachable in the classes' protocol). Hardening only.
- web/worker-runtime.js does not split getRandomValues requests at 65,536 bytes; the largest draw is 1,024 bytes and a larger one would fail closed with RANDOM_FAILED. uniform_below could loop on a malfunctioning host source that returns only rejected values (availability only).
- Documented threat-model limits confirmed: JavaScript strings cannot be erased; WebAssembly memory of a terminated worker is freed without overwrite; panic = abort (Cargo.toml:99) applies to native and wasm32 release builds, so a trap runs no destructor; Ctrl+C ends the CLI without wiping; the standard library's stdin buffer is outside the program's control; the menu and ctrl-c threads are not filtered; host compromise is out of scope.
- AUD-009's informational note on password-generation drop order is resolved by LockedText::build; the same pattern remains in Password::new and edit_line (AUD-010-SEC003).
- Availability, page-chosen and self-limiting: MhfeWallet.drawPhrase accepts any number of workers; Password::new walks the whole NFKD input even past 1,024 bytes and normalized_passphrase reserves 11 times the passphrase length; there is no message-size limit between page and worker.

browser-package:

- web/runtime.js exports ten internal helpers that runtime.d.ts does not declare (WorkerJob, OperationSlot, describeChoice, encodeSecret, requireBoolean, requireCallback, requireText, secretBuffers, sentence, wipeSecrets); the classes use them by composition. The internal surface could be documented as such.
- WorkerJob accepts a 'result', progress or ask before any 'ready'; every worker of this build says ready first. The published v0.5.0 worker has no handshake and fails closed with a generic error, not PACKAGE_MISMATCH. Recommendation: refuse any reply before 'ready'.
- The worker serves requests with unexpected properties and ignores them; the classes ignore unknown option fields (a misspelt 'samelength' leaves the documented 24-word default). No field is read as a URL, method or file name.
- MhfeWallet.drawPhrase({ workers }) has no upper bound (64 gave 64 workers, each with its own passphrase copy); the default is min(hardwareConcurrency, 8).
- CompiledModule caches a rejected compilation (no retry); PackageCheck then closes the class for good with a detail naming a missing 'wasm-unsafe-eval', also for a transient failure such as memory pressure.
- Coin ids are trimmed and lower-cased (' Bitcoin ' is bitcoin). The INVALID_COIN message lists all 12 coin ids, so a Dash-edition page that passed an unknown id would show other coins' names at run time; static page scripts name no coin.
- requireSamePassword makes transient UTF-8 copies to compare a byte password with its repetition before the startup check has passed, and wipes them at once; docs/BROWSER-PACKAGE.md says secrets are copied only after the check. The wording could be qualified.
- Some refusals described as 'before any Argon2 work' (NO_BUILT_IN_CHECK and NO_WALLET_CHECK in check) come after the 1 MiB Argon2 known answer, though before any round; the documentation wording is slightly broader than the code.
- Self-check timings in this run: startup checks 10 to 107 ms (documented: about 15 to 210 ms), MhfeClient.fullCheck 0.8 to 1.3 s (documented: one to two and a half seconds). Consistent in magnitude and machine-dependent.
- fullCheck() is not bound to the long-operation slot and cancel() does not stop it; consistent with the documentation, as it runs in seconds.
