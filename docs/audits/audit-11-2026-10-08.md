### Findings

#### AUD-011-SEC001 - Low - Hidden-wallet repetition encoding leaves the first owned password copy unwiped on refusal

- **Category / severity / status:** SEC / low / open.
- **Release blocking:** false; limited impact demonstrated, no exploitable disclosure or wrong cryptographic output established.
- **Affected files:** `web/client.js:660`, `web/client.js:661`, `web/runtime.js:encodeSecret`.
- **Reproduction:** Obtain an ordinary ready hidden-wallet session. Call session.open({password:'synthetic-test', passwordRepeat:'\uD800'}). requireRepetition accepts both string types. The first encodeSecret allocates an owned Uint8Array; the second rejects malformed UTF-16 with INVALID_PASSWORD_TEXT. Instrument TextEncoder to retain that first array and observe nonzero bytes after rejection.
- **Expected:** Every package-owned secret buffer is zeroed on all fallible request-construction paths, without changing caller-owned buffers.
- **Observed:** Object-literal evaluation allocates the password before repetition encoding. The exception occurs before assignment of message and before sendRequest/wipeSecrets, so the first allocation has no cleanup owner.
- **Impact:** Local residual-memory lifetime defect on malformed repeated input. No network disclosure, secret theft, access from another process, or guaranteed persistence beyond garbage collection was demonstrated. Caller-owned strings cannot be securely wiped by JavaScript regardless.
- **Evidence:** AUD-011-harnesses/browser/secret-refusals.mjs; local secret-refusals.log exits 1 with first-copy wipe assertion.
- **Challenge:** Independent package reviewer accepted the unchanged public method reproduction. Mock worker/startup bypass only establish session readiness; they do not replace the encoding path or demonstrate real browser startup.
- **Historical relationship:** AUD-009-SEC001 affected passwords.js and wallet.js and remains historically verified by AUD-010. This is a new hidden-session occurrence introduced by replacing equality-checking requireSamePassword with type-only requireRepetition.
- **Recommended fix:** Construct the request incrementally inside a cleanup guard, using the same guarded secret-request pattern as other public operations. Wipe all already allocated buffers if any subsequent encoding fails.
- **Required verification:** Add public hidden-session regression for malformed repetition, second-buffer allocation failure and request-send failure; assert owned first copies are zeroed, caller buffers preserved, no worker request sent, and a subsequent valid open succeeds.

#### AUD-011-ARC001 - Low - CLI password-size refusals discard and duplicate library-owned error messages

- **Category / severity / status:** ARC / low / open.
- **Release blocking:** false; limited impact demonstrated, no exploitable disclosure or wrong cryptographic output established.
- **Affected files:** `src/bin/mhfe/diceware.rs:147`, `src/bin/mhfe/diceware.rs:218`, `src/new_password.rs:53`, `src/new_password.rs:72`.
- **Reproduction:** Inspect PasswordRecipe::words/characters: both author InvalidPasswordSize text. CLI run/run_characters call these constructors but discard their errors and rebuild 'Choose between 1 and {MOST_*} words/characters'. The limits are imported, but the refusal wording has two owners.
