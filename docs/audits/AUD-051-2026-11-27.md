### Findings

#### AUD-051-SEC001 — Medium — Cancellation can leave the private terminal screen visible

- **Status.** Open. Release blocking because handled cancellation can leave private material visible.
- **Evidence.** `src/bin/mhfe/terminal.rs:790–796,828–836`, `src/bin/mhfe/hidden_input.rs:187–193`, `src/bin/mhfe/encrypt.rs:380–404`.
- **Observed behavior.** The ordinary screen exit clears its active flag before terminal output completes and outside the drawing guard. The cancellation handler sees the flag clear and can exit before the terminal receives the screen-clearing sequence.
- **Impact.** A handled cancellation can leave typed mnemonic words or other private output visible in the foreground terminal. Ordinary interactive input with redirected stdout can use a private screen independently of Flow. No disclosure was observed at runtime.
- **Recommended fix.** Serialize screen entry, physical teardown and cancellation with one guard. Keep a guard-aware helper for cancellation to preserve lock ordering.
- **Verification.** Verify the corrected invariant on the relevant target using public fixtures and retain the exact revision.

#### AUD-051-SEC002 — Low — Unix terminal restoration waits for output to drain

- **Status.** Open. Bounded to the affected surface.
- **Evidence.** `src/bin/mhfe/hidden_input.rs:164–193,792–798`, `src/bin/mhfe/terminal.rs:385–389`. [Linux termios](https://man7.org/linux/man-pages/man3/termios.3.html)
- **Observed behavior.** Both ordinary and signal cleanup restore terminal settings with TCSAFLUSH, whose contract waits for pending terminal output.
- **Impact.** With device or driver output flow stopped, echo and mode restoration and handled cancellation can remain pending. The clean source does not establish the behavior of any particular real terminal during a stop.
- **Recommended fix.** Use the audited SPC restore semantics: discard pending input and restore immediately, preserving retry and error policy. Check the restore operation on Linux and macOS.
- **Verification.** Verify the corrected invariant on the relevant target using public fixtures and retain the exact revision.

#### AUD-051-SEC003 — Low — The browser can terminate a worker before its final secret wipe

- **Status.** Open. Bounded to the affected surface.
- **Evidence.** `web/worker-runtime.js:126–132`, `web/runtime.js:235–239`, `docs/BROWSER-PACKAGE.md:983–996`. [HTML worker termination](https://html.spec.whatwg.org/multipage/workers.html#terminate-a-worker)
- **Observed behavior.** The worker queues its terminal reply before its finally block wipes transferred buffers. The page immediately terminates the worker when it receives that reply.
- **Impact.** The browser may interrupt the worker at successful or rejected completion before its owned request arrays are wiped. The finding concerns early cleanup, with no demonstrated readback.
- **Recommended fix.** Wipe the request before sending either terminal reply. Keep immediate cancellation behavior and document its independently limited cleanup.
- **Verification.** Verify the corrected invariant on the relevant target using public fixtures and retain the exact revision.

#### AUD-051-SEC004 — Low — Missing-word search retains unzeroized copies of container indices

- **Status.** Open. Bounded to the affected surface.
- **Evidence.** `src/search.rs:58–64,103–112,265–271`, `src/phrase.rs:87–104,129–136`, `SECURITY.md:47–68`.
- **Observed behavior.** ContainerSearch owns typed container indices in an ordinary Vec. Producing a candidate clones the Vec, and words_of builds an ordinary vector of ordered word references before joining them.
- **Impact.** Controlled intermediate copies of protected container data can remain in freed heap memory. The input here is an encrypted container and the audit establishes no direct mnemonic or password exposure.
- **Recommended fix.** Use zeroizing storage from parsing through candidate reconstruction and build the output without an unprotected intermediate vector of word references.
