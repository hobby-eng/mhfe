### Findings

#### AUD-047-SEC001 — Low — mhfe decrypt asks for the BIP39 passphrase where no 24-word reading can come out

- **Category:** SEC.
- **Severity:** low.
- **Status:** fixed.
- **Release blocking:** false.
- **Affected files and builds:** src/bin/mhfe/decrypt.rs:194-195, 440-459.
- **Rules:** CORE-49.
- **Reproduction:** mhfe decrypt --words 12 on a 24-word container (the `checked` case, one password): the question 'Is a BIP39 passphrase used with the original seed phrase?' and the passphrase prompt come before the work; in script mode with --passphrase-used yes a line is read.
- **Expected behavior:** With a stated length of 12 to 21 words the core gives only short readings, which have no 16-bit check, so the passphrase is not asked (HEAD asked only when a 24-word reading came out).
- **Observed behavior:** source_check_passphrase asks whenever the container offers the wallet check; tell_source_check prints nothing for the short readings.
- **Impact:** A secret is asked and held for nothing, and a script's input line is consumed.
- **Evidence:** Source reading by reviewer A; the condition is container.offers_wallet_check() alone.
- **Recommended fix:** Skip the question in the `checked` case, as for one password and a stated short length.
- **Required verification:** A terminal case of decrypt --words 12 that goes from the password to the memory reservation with no passphrase question.

#### AUD-047-SEC002 — Low — Under a small locked-memory limit the summary can still reflect that several passwords were typed

- **Category:** SEC.
- **Severity:** low.
- **Status:** fixed.
- **Release blocking:** false.
- **Affected files and builds:** src/bin/mhfe/decrypt.rs:188-195; src/bin/mhfe/terminal.rs:41-49.
- **Rules:** CORE-24.
- **Reproduction:** Linux with `ulimit -l 64`, a 24-word container, about ten extra passwords, then 'Yes' to the passphrase question: the kept Passwords hold locked pages, the passphrase line may fail to lock, and note_unlocked writes its warning on the record. On Windows, the reservation of a larger level made off the record replaces the first level's on-record page-file notice and 'Disk' answer.
- **Expected behavior:** The summary is the same for one password or several (AUD-007-SEC005, decrypt.rs:181-182).
- **Observed behavior:** The locked-memory warning, and on Windows the page-file notice, can depend on the number or settings of the extra passwords.
- **Impact:** A weak signal on the main screen of how many passwords were typed, only under an unusually small limit or on Windows with other settings.
- **Evidence:** Source reading by reviewer A, checked by the coordinator against note_unlocked and reserve_largest.
- **Recommended fix:** Ask the 16-bit-check passphrase before add_passwords, and keep the Windows notice of a larger level off the record or say it as for one password.
- **Required verification:** A terminal case with a lowered memlock limit comparing the summaries of one and of several passwords.

#### AUD-047-SEC003 — Low — On a Windows console the scroll view and the password headings write secrets through std's stderr

- **Category:** SEC.
- **Severity:** low.
- **Status:** fixed.
- **Release blocking:** false.
- **Affected files and builds:** src/bin/mhfe/scroll.rs:140-150; src/bin/mhfe/decrypt.rs:420-433; src/bin/mhfe/style.rs:398-401.
- **Rules:** RUST-13, CORE-24.
- **Reproduction:** Every redraw of the scroll view writes the kept phrase rows and 'Password N: ...' with anstream's eprintln to io::stderr(); on a Windows console std converts each line to UTF-16 in a stack buffer it does not wipe.
- **Expected behavior:** Secret lines go through the raw writer that print_phrase uses (raw_io.rs), past std's buffers.
- **Observed behavior:** Whole phrases and passwords pass through std's console conversion once per key press.
- **Impact:** Unwiped copies on the stack of a Windows process; Unix writes the bytes directly.
- **Evidence:** scroll.rs draws kept lines with eprintln!("{line}") (confirmed by the coordinator).
- **Recommended fix:** Write kept lines and password headings through raw_io.
- **Required verification:** A Windows terminal run and a code review of every writer of kept lines.

#### AUD-047-FUN001 — Low — An address that two coins share searches their common root twice

- **Category:** FUN.
- **Severity:** low.
- **Status:** fixed.
- **Release blocking:** false.
- **Affected files and builds:** src/rehearsal.rs:700-706; src/wallet.rs:221-231, 915-948, 991.

- **Reproduction:** Compare a non-matching '0x...' address read with Address::parse_any: Ethereum searches 44'/60', then Ethereum Classic 44'/61' and 44'/60' again (coin types [61, 60]); a '1...' address searches 44'/0' for Bitcoin and 145' and 0' for Bitcoin Cash.

- **Recommended fix:** Skip a root that an earlier coin of the same address form already searched.
- **Required verification:** A unit test counting the stopped() calls with SearchLimits::new(1, 1).
