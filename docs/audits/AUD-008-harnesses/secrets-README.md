# AUD-008 native secret and isolation probes

These bounded probes belong to the MHFE pre-release review at HEAD `01978aa01f86cbec7dbc9fb9afd131dfa1a1d650` and the recorded dirty source bytes. They use only public BIP39 reference entropy or synthetic passwords/datagrams. They execute no Argon2 operation or full vector replay. Source hashes and actual compile commands are retained in the local `../AUD-008-evidence/secrets-*` records.

Run from the authoritative MHFE repository root. Existing matching pinned Rust dependency `.rlib` files under `target/debug/deps` are required; the scripts select the newest library for each needed crate and use the repository's Rust toolchain homes. They do not invoke Cargo or download dependencies.

- `python3 docs/audits/AUD-008-harnesses/secrets-format.py` extracts the actual new-wallet formatter expression and the actual reserved formatter, then counts allocated blocks released with a public mnemonic prefix under an allocator that moves every reallocation. At the baseline it prints `4` current-formatter copies and `0` reserved-formatter copies and exits 1. A fully repaired source expression requires reassessing the extraction guard before rerunning; this guard never silently counts an unrelated expression as fixed.
- `python3 docs/audits/AUD-008-harnesses/secrets-password-lock.py` extracts the actual hidden-password retention expression and observes `/proc/self/smaps`. Sixteen synthetic 1024-byte passwords are locked while owned by `Password`; after those objects drop, the retained duplicate buffers are still alive. At baseline the original pages are `16/16` locked and the retained pages `0/16`; exit 1. Exit 2 means original locking was refused and the diagnostic is blocked.
- `python3 docs/audits/AUD-008-harnesses/secrets-uring-build.py`, followed by `python3 docs/audits/AUD-008-harnesses/secrets-uring-run.py`, compiles and executes the exact production Linux isolation module with a tiny C helper. A pre-existing loopback receiver is a test observer only; the sender socket is newly created after isolation by a two-entry io_uring. The helper sends one fixed public 29-byte marker to 127.0.0.1. Ordinary socket creation must fail while both isolation flags report true. Exit 1 means the new io_uring socket successfully sent the marker through the asserted boundary; exit 0 means it could not create a socket; exit 2 means host policy or an unsupported ring operation blocked the diagnostic. A generic task sandbox may refuse the initial receiver; the recorded host run was a separately authorized narrow escalation, with the original sandbox failure retained.

The io_uring probe requires Linux 5.19 or later, io_uring enabled, a C compiler and the system Linux UAPI headers. It creates no external-network request, modifies no application protection setting, and writes no data from inside the isolated child process. Build/command logs and binaries stay in ignored local evidence. The original nonexistent-libc-path compile mistake is preserved as a harness failure, separately from the corrected build and product reproduction.

These probes establish bounded allocation, page-map and isolation behaviors. They do not recover secrets from swap, prove physical erasure, certify upstream cryptography, replay a complete interactive CLI workflow, or establish that a production dependency is currently malicious.
