MHFE 0.7.0 implements suites `MHFE-BIP39-256-EXPERIMENTAL-3` and `MHFE-BIP39-LP-EXPERIMENTAL-4` and
the optional profiles MHFE-REPAIR-1, MHFE-PASSWORD-CHECK-1 and MHFE-WALLET-CHECK-SEED-1, as defined
by [specification v0.7.0](https://github.com/hobby-eng/mhfe-spec/releases/tag/v0.7.0). Its suites
are those of v0.6.0, and passwords may now hold the characters of Unicode 18.0.0. Every password
that was valid before keeps its bytes, so containers made with versions 0.4.0 to 0.6.0 stay
readable. A container whose password uses a character new in Unicode 18.0.0 needs this version or
a later one.

The cipher now comes from the crate [mhfe-core](https://github.com/hobby-eng/mhfe_core), pinned in
`Cargo.toml` to its commit 523f9e4. That commit follows mhfe-core's 0.2.0 release: a cancelled
operation is a result there, not an error. The browser package and the Rust library changed
incompatibly, hence the version 0.7.0. Version 0.6.0 stays published as it is; these notes list
what changed after it.

## New

- **`mhfe decrypt` takes several passwords.** At a terminal it asks after each password whether to
  recover now or to add another, each with its own PIM and memory level. Every question comes
  before the work, the BIP39 passphrase too. Each phrase appears under its password as soon as it
  is recovered, on one private screen that then scrolls, and the summary records one password,
  however many were typed. The start menu calls it "Recover one or more seed phrases from a
  container".
- **`mhfe check` compares the wallet without the passphrase too.** With a BIP39 passphrase, an
  address or the fingerprint is compared with the wallet with it, then with the wallet without it.
  The result says which matched. A match of the second confirms the phrase, not the passphrase;
  when the passphrase typed passes the 16-bit check, the result says that it is very likely right.
  `mhfe rekey` takes only a reference of the wallet with the passphrase.
- **The coin is told from the address.** The question about the coin is gone. An address is searched
  as every coin whose form it has: `1…` as Bitcoin and Bitcoin Cash, `3…` as Bitcoin and Litecoin,
  `0x…` as Ethereum and Ethereum Classic. `--coin` limits the search to one coin, and a script
  without it no longer means Bitcoin. The coins appear as soon as the address is read, and a root
  that two coins share is searched once.
- **The menu offers passwords from real dice.**

## Changed

- **The cipher comes from mhfe-core.** So do the password rules, native Argon2 and the protection of
  secrets. Containers, phrases, repair words and check words stay the same.
- **Nothing secret reaches swap on Linux.** A command that reads secrets forbids itself swap before it
  starts. Where it cannot and swap is not encrypted, it asks whether to go on.
- **Isolation on every system.** Every command but `serve` closes itself off before it reads
  anything, and warns of a protection that did not take effect. On Windows the network stays open,
  and every command says so.
- **More secrets stay in locked memory,** among them the BIP32 keys and the word hints. On Linux they
  lie in the kernel's secret memory where it is offered.
- **The menu runs each command as a process of its own.** A crash no longer takes the menu with it.
- **`mhfe check` can answer "not verified".** A 24-word phrase without an address or fingerprint gets
  this answer instead of "does not match". The exit code stays 3.
- **`mhfe check` names every length that matches.**
- **The BIP39 passphrase comes before the address.** `mhfe check`, `mhfe rekey` and a search for
  missing words ask for the phrase's passphrase first, then for the address or fingerprint. `mhfe
  check` asks it right after the password, before what to compare with, and offers the phrase +
  passphrase check only when one was typed. A script of `check --stdin --address` or
  `--fingerprint` gives the passphrase line before the reference now, and `decrypt --stdin
  --passphrase-used yes` reads its passphrase line for every 24-word container unless `--words`
  states 12 to 21, no longer only when a 24-word reading comes out.
- **The summary is shorter.** The work and the isolation that holds are gone from it. The time
  appears only for settings above the default, and swap or memory that could not be locked only
  when they are a risk.
- **`--stdin` at a terminal changes nothing,** so a typed secret stays hidden.
- **A refused command line no longer repeats what was typed.**
- **A new phrase with the wallet check takes a minute or two more.** It is drawn on one thread, as the
  specification's proof requires.
- **`mhfe test-vectors` is gone.** The test vectors live in the specification's repository.
- **A wrong answer is asked again.** At a terminal, a container that the command cannot use, a
  phrase too long for `--same-length`, and a line too long or not UTF-8 no longer end the command.
- **Every help ends with the safety line.**

## Removed

- `mhfe new` no longer asks for a chosen word, and `--never-use` is gone. Every word of a new phrase
  is random. The browser package keeps its chosen word.
- `mhfe wallets` is gone, and the start menu has one entry less. `mhfe decrypt` with several
  passwords shows hidden wallets instead: a password is typed once, and a phrase that passes a check
  is marked as verified instead of refused. The browser package keeps `openHiddenWallets()`.

## Fixed

- Ctrl+C while a typed line or a phrase was being drawn could leave its last part, such as the hint
  below a password, on the main screen.
- A key pressed early no longer clears a private screen.
- Ctrl+C, Ctrl+\ and Ctrl+Z end a command in its checks at start too.
- Ctrl+D at any empty prompt cancels, with exit code 130.
- A result that cannot be written ends with exit code 1 instead of a success or a crash, as long as
  standard error can still be written.
- A pasted line too long for any answer no longer leaves its rest to answer the next question.

## Browser package

- `check()` gives `outcome` beside `matches`, and `withoutPassphrase` when an address or the
  fingerprint matched only the wallet without the passphrase given.
- The `coin` of an address reference and of `describeAddress()` is optional. Without it the address
  is searched as every coin whose form it has, a root that two coins share once, and
  `describeAddress()` names those coins in `coins`.
- `drawPhrase()` uses one worker, and its `workers` option is gone. It also refuses a repetition of a
  passphrase that was not typed, and gives up with `RANDOM_FAILED` after 64 times the draws it
  expects.
- `cancel()` is no error any more: the operation resolves to `CANCELLED`, `{ cancelled: true }`.
  `MhfeCancelledError` and the code `CANCELLED` are gone.
- The export `checkPassword` is gone; `encrypt` and `decrypt` check the password as before.
- `make()` with a `count` for "checkWord", and an owner's answer to `onConfirmAgain` with a length
  the owner cannot compare, are refused by the library with `INVALID_REQUEST`, no longer by a
  `TypeError` of the class. An owner's `words` in that answer must be a word count.
- A self-check part that failed closes the class even if its worker then crashes.
- The Argon2 builds clear their stacks and run only in a worker.
- `MhfeRepair`'s check at start also covers the seed, BIP32 and the hashes of the fingerprint.

## Library

- `Mhfe`, `Password`, `Suite`, `WorkFactor`, `Phrase`, `Argon2Engine` and `NativeArgon2` are
  mhfe-core's. The operations are functions that take `Mhfe` first.
- `wallet::find_addresses_until` searches an address read as several coins, a shared root once;
  `AddressSearch::coins` names the coins searched.
- An operation that a callback can stop returns `Outcome<T>`, `Continue` with its result or
  `Break`; `MhfeError::Cancelled` is gone. `repair`, `new_password` and `wallet` refuse with errors
  of their own, which turn into `MhfeError`.
- `CheckOutcome` has a third value, `NotVerified`.
- `Reference::Address` and `ReferenceTarget::Address` hold `addresses`, read by
  `Address::parse_any` or `Address::parse_with` as every coin of an address's form, and
  `AddressSearch::new` takes them. `CheckEvidence::without_passphrase` says that a check matched
  the wallet without the passphrase given.
- `check_container`, `recover_confirmed`, `SelfCheckReport::warnings` and `require_passed` are gone.
  Use `ContainerFacts::read`, `rekey::Rekey` and `first_failure()`.
- `random::uniform_below` refuses a range it cannot draw from and a source that never gives a usable
  value, instead of stopping the program or waiting for ever.
- `docs/API.md` lists everything removed or replaced.

## Build, tests and release

- A clone needs `--recurse-submodules`: the vectors come from the specification.
- The tools are `cargo xtask`, dprint replaces Prettier, and Node.js is gone. The terminal cases,
  the licence list, the cell width table and the checks of the fast-mode launcher moved from Python
  to `cargo xtask`. The only Python left is the launcher itself.

## Reviews

Audit records are in [`docs/audits/`](https://github.com/hobby-eng/mhfe/tree/v0.7.0/docs/audits).
AUD-044 audited mhfe on mhfe-core before this release and found 5 medium and 100 low problems, all
fixed. AUD-045 audited the whole repository. Its one medium finding, Ctrl+C leaving words of a
secret on the main screen, and three of its four low ones are fixed. The fourth, browser JavaScript
without a TypeScript check, is accepted: the page checks run that code in Chrome and Firefox.
AUD-046 audited the result and found 3 medium and 29 low problems. All are fixed but one low one,
AUD-046-UI005: a container that does not fit the command is refused only after its repair words and
a search for missing words, which can run a full recovery for each candidate. The refusal still
comes before the password is asked for. The fix of the Ctrl+C finding has no automated test; a probe
kept with AUD-045 reproduces the race.
