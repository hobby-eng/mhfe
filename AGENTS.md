# mhfe agent instructions

This repository is part of the `bip_tools` workspace. If a workspace `AGENTS.md` exists one directory above this repository, read and follow it first. Its core rules: edit only this checkout in place, never create another copy or worktree, never delete project directories, use the toolchains it names, use only public test data, do not commit or push without an explicit request, and write everything in English only (code, comments, commits, documentation).

The specification and vectors for this implementation live in `../mhfe_spec`; an algorithm or vector change must be checked against both. The repository keeps no vector files of its own: the program and the tests read them through the submodule `tests/spec`, pinned at the specification's tag v0.7.0. Clone with `--recurse-submodules`, or run `git submodule update --init`. The cipher, native Argon2 and the protections of secrets are the crate `mhfe-core`, pinned in `Cargo.toml`, from `../mhfe_core`: a change to them is made there and comes here with a new version of the crate.

## Commands

- Toolchain: Rust 1.99.1 from `rust-toolchain.toml`, with the `CARGO_HOME` and `RUSTUP_HOME` set in the environment (never the home-directory defaults). Emscripten 6.0.12 from `../workingspace/emsdk` (`source ../workingspace/emsdk/emsdk_env.sh`) for the browser builds. The fuzz targets in `fuzz/`, a workspace with its own lockfile, run with `nightly-2026-11-13` and cargo-fuzz 0.13.2: `cargo +nightly-2026-11-13 fuzz run --fuzz-dir fuzz <target>`; their libfuzzer-sys compiles libFuzzer, so `scripts/check.sh`, which lints them, needs a C++ compiler.
- Targeted: `cargo test --locked <name>` (fast: the tests use a reduced Argon2 cost); `cargo clippy --locked --all-targets --all-features -- -D warnings`; for the tools in `xtask/`, `cargo clippy --locked --package xtask --all-targets -- -D warnings` and `cargo test --locked --package xtask`; `cargo xtask copies` (code copied from one place to another); `cargo xtask code-rules` (file lengths, script headers, lint reasons, exact versions, tight Markdown lists); `cargo clippy --locked --lib --target wasm32-unknown-unknown --features wasm -- -D warnings`; `cargo fmt --all --check`; `dprint check` (dprint 0.63.0 for Markdown, JSON, TOML, YAML and the JavaScript of the check pages in `xtask/pages/`; `dprint.json` pins its plugins).
- Browser package: `scripts/build-wasm.sh`, then `cargo xtask wasm verify dist`; `MHFE_BROWSERS=DIR cargo xtask package-check` and `MHFE_BROWSERS=DIR cargo xtask browsers` run it in the pinned Chrome for Testing and Firefox at a reduced cost (DIR holds them unpacked, as `.github/actions/browser-checks` lays them out); `MHFE_BROWSERS=DIR cargo xtask parity` compares it with `target/release/mhfe`; `cargo xtask browser-check-page` writes a full-size page for a real browser.
- The terminal cell table `src/bin/mhfe/cell_widths.rs` is generated: `cargo xtask cell-widths` (`--check` compares; `scripts/check.sh` runs it), from the Unicode 18.0.0 data in `tests/fixtures/unicode18-ucd/`.
- The terminal cases: `cargo xtask terminal [program]` (a pseudo-terminal on Linux and macOS, a pseudo-console on Windows); the fast-mode launcher: `cargo xtask fast-mode`; the Rust crates part of `THIRD_PARTY_NOTICES.md`: `cargo xtask licences` (`--check` compares). The only Python left is `packaging/mhfe-fast-mode.py`, the launcher for a computer without mhfe.
- The table of published rounds `src/mhfe/published_rounds.rs`, which the self-checks replay, is generated from `tests/spec/vectors/`: `cargo xtask published-rounds` (`--check` compares; `scripts/check.sh` runs it).
- Full-size runs (announce first; the user runs full suites): `cargo test --release --lib full_size -- --ignored`; `MHFE_BROWSERS=DIR cargo xtask package-check --full`.
- Release-level (explicit request only): `scripts/check.sh`; `scripts/check-release-artifacts.sh`; `scripts/build-reproducible.sh` (`packaging/Dockerfile.reproducible`) and `canonical-output/release/SHA256SUMS`.
- Workflows: `.github/workflows/ci.yml`, `audit.yml`, `release.yml`.
- Release notes: `docs/releases/v<version>.md`, written before tagging from the draft `docs/releases/unreleased.md`; `release.yml` attaches that file to the draft release and refuses a tag without it, and creates the draft only after `ci.yml`, which it calls, has passed on the tagged commit; the maintainer publishes it after signing (`docs/RELEASING.md`).

## Audits

An audit, a review of findings or a remediation follow-up of this repository follows the workspace's audit procedure in `../.github/audits/`: `FULL_AUDIT_GUIDE_V2.md` (the checks and their order; section 17 for Rust crates and every target they are built for), `AUDIT_STANDARD.md`, `AUDIT_TEMPLATE.md` and `audit-report.schema.json`. `docs/audits/TARGETS.md` lists the targets, their runners and the fuzzing budgets that section 17 asks for. Reports, their JSON twins and their harnesses stay in this repository's `docs/audits/`.
